# `e2e/` — מדריך הפעלה הנדסי ופנקס אינווריאנטים (Testing & E2E Runbook)

> **ספר הפעלה תפעולי לכתיבה, תחזוקה והרצת בדיקות קצה-לקצה (E2E) ובדיקות עשן ב-Playwright**  
> נטען אוטומטית בעבודה על קובצי בדיקות ותרחישי דפדפן. מפה מלאה: [docs/CODE_MAP.md](../docs/CODE_MAP.md).

## 1. שערי איכות ופקודות הרצה מקומיות (Quality Gates & Commands)

| פקודה | תפקיד ופירוט | סף מעבר מחייב |
|---|---|:---:|
| `npm run test:e2e` | הרצת סוויטת בדיקות E2E מלאה מול שרת Preview קפוא (פורט 4173, `playwright.e2e.config.js`) | 100% ירוק |
| `npm run smoke` | בדיקת עשן חיה ומהירה במסע לקוח מול שרת פיתוח חי (פורט 5173, `playwright.config.js`) | קוד יציאה 0 |
| `npx playwright test <file>` | הרצת קובץ בדיקה בודד לצורך איתור תקלות ממוקד | מעבר נקי |

## 2. חוקי ברזל ארכיטקטוניים ואינווריאנטים (Architectural Invariants)

1. **איסור מוחלט על הזרקת שורות בדיקה למסד הנתונים:**  
   המערכת פועלת מול מסד נתונים יחיד המשרת גם את סביבת הייצור. **חל איסור מוחלט להכניס שורות בדיקה (INSERT/UPDATE מלאכותי) לבסיס הנתונים החי.**  
   התבנית הבלעדית לבדיקות תרחישים היא **יירוט רשת ב-Playwright (`page.route`)** — מזייפים את תשובת ה-API של הדפדפן, לעולם לא את תוכן המסד.
2. **איסור על קידוד מזהים קשיחים (Dynamic Fixtures):**  
   רשומות חיות במסד משתנות (הצעות פגות תוקף, פרויקטים נסגרים, מונים גדלים). אין לקבע מזהה רשומה ספציפי (כגון `quote_id = 6`). בחירת פיקסטורה לבדיקה נעשית תמיד בזמן ריצה לפי תנאי שאילתה ("ההצעה הפתוחה הראשונה שיש לה שורת דיילות").
3. **הפרדת סביבות הרצה — Dev מול Preview:**  
   - `npm run test:e2e` רץ אך ורק מול שרת Preview קפוא (בנדל מוכן על פורט 4173) כדי למנוע רענוני Vite HMR פתאומיים שקורעים סשנים של התחברות באמצע בדיקה.
   - `npm run smoke` מיועד לבדיקה חיה ומהירה ומורץ מול שרת ה-Dev (פורט 5173).
4. **אבטחת סודות וקרדנצ'לס:**  
   סודות ומשתמשי בדיקה נקראים אך ורק ממשתני סביבה (`E2E_*` ב-`.env.local`). לעולם אין להדפיס או לקודד סודות, סיסמאות או מפתחות בקובצי הבדיקות או בלוגים.

## 3. פנקס מלכודות שקטות בבדיקות (Silent Traps Register)

| מלכודת שקטה | מדוע הבאג שורד ללא שגיאה | התוצאה והפתרון ההנדסי המחייב |
|---|---|---|
| **משטח צף שנסגר ב-`blur`** | לחיצה באמצעות `locator.click()` מעבירה פוקוס וסוגרת פאנל צף לפני שאירוע הלחיצה נקלט בפועל | שימוש בתבנית פיזית: `page.mouse.down()` ➔ המתנה קצרה (~300-400ms) ➔ `page.mouse.up()` |
| **מדידה שהמכנה שלה 0** | סריקת DOM או חיפוש אלמנטים על שלד טעינה (Skeleton) מחזירים מערך ריק של 0 שגיאות ונראים ירוקים | כל בדיקת אוסף חייבת להמתין להופעת התוכן האמיתי ולאמת מפורשות `expect(items.length).toBeGreaterThan(0)` |
| **זיהום פיקסטורות עצמי בחבילה** | בדיקה שמשגרת דוא"ל גורמת לבדיקה הבאה להיתקל בדיאלוג `window.confirm` ("ההצעה כבר נשלחה"). Playwright דוחה דיאלוגים כברירת מחדל והבדיקה קורסת | הגדרת טיפול בדיאלוגים ב-`beforeEach` (`page.on('dialog', d => d.accept())`) |
| **בדיקת מצב UI ללא אימות DB** | בדיקה המאמתת רק שהכפתור נלחץ והמודאל נסגר עשויה להציג ירוק גם כשקריאת ה-API נכשלה בשקט | אימות תוצאת הפעולה בנתונים המוחזרים או משיכת הנתון המעודכן |
| **קידוד מונה קשיח שמתיישן** | בדיקת כפתור עם טקסט `(0)` נופלת יומיים לאחר מכן כאשר רשומה אמיתית מגיעה לסיום תוקף ומעלה את המונה ל-`(1)` | אימות הקשר הלוגי והאינווריאנט: בדיקה שהכפתור מנוטרל אם המונה בתווית הוא 0, ומופעל אם המונה גדול מ-0 |

## 4. מוסכמות קוד ודפוסי בדיקה (Testing Conventions)

1. **איתור משתמשים לפי תפקיד:** פתרון משתמשי בדיקה מבוצע לפי מיפוי `role -> email` ממשתני הסביבה, ולא לפי מזהה משתמש סטטי.
2. **אימות כפול לפני ייחוס כשל לשינוי אחרון:** כשל בבדיקת E2E מחייב הרצה חוזרת של הבדיקה כדי לפסול תלות סדר או מצב רשת לפני שמסיקים שמדובר ברגרסיית קוד.
3. **הסרת ספקי ראיות זמניים:** סקריפטים זמניים שנועדו לבצע צילומי מסך או מדידות חד-פעמיות אינם מתווספים למאגר ונמחקים לפני ביצוע קומיט.
