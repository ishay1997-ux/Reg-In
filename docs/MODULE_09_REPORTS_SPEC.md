## 1. תמצית מנהלים, חזון ומתודולוגיה הנדסית

מודול הדיווח והמודיעין העסקי (BI & DSS) של מערכת **Reg-In** פותח כמענה לצמיחה המואצת של החברה: מעבר מ-221 פרויקטים ב-2024 ל-304 פרויקטים ב-2026, ניהול מעל 5.1 מיליון ₪ הכנסות, 61 לקוחות עסקיים ומוניציפליים, ומאגר של 186 דיילות.

### מתודולוגיית הנדסת תעשייה וניהול (IE&M Principles):
1. **Lean & Waste Reduction:** הימנעות מוחלטת מ-Over-engineering. במקום שרתי Python/ML מנופחים הדורשים תחזוקה שוטפת ועלויות ענן כבדות, המערכת מנצלת את כוח המחשוב הקיים ב-PostgreSQL ובדפדפן באמצעות **חקר ביצועים וסטטיסטיקה מיושמת (Empirical Heuristics & OR)**, המספקים 95% מהדיוק באפס שיהוי (Zero Latency) וללא עלות תשתית נוספת.
2. **Single Source of Truth (SSOT):** כל הנתונים הפיננסיים נשאבים ישירות מפונקציית השרת המאומתת `finance_project_money` (מיגרציה E1). שום מספר אינו מחושב מחדש בצד הלקוח.
3. **Actionable In-Context Analytics:** תובנות החיזוי אינן נשארות כלואות בלשונית דוחות פסיבית ("בית קברות לגרפים"), אלא מוזרקות ישירות למסכי העבודה השוטפים (מסך שיבוץ דיילות, עריכת הצעת מחיר, ומסך הגבייה).
4. **אבטחת איכות והפרדת רשויות מול בינה מלאכותית (GenAI Guardrails):** מודל השפה (Google Gemini) אינו מחשב מתמטיקה או כספים. הוא מקבל נתונים מאומתים ומבצע סינתזה אנושית, ניתוח סנטימנט איכותני והפקת טיוטות שימור.
5. **חוג בקרה סגור וכיול היפר-פרמטרים (Closed-Loop Feedback & Hyperparameter Optimization):** מודול הדוחות סוגר מעגל מול אלגוריתם השיבוץ החכם (`src/lib/smartMatch.js`) – הוא מודד את שיעור אימוץ המלצות דרג 1, את גמישות משקולת המרחק, ואת מדד אי-השוויון של ג'יני ($G$) לחלוקת משמרות הוגנת, ומייצר המלצות כיול אוטומטיות לפאנל ההגדרות (`SmartMatchPane.jsx`) למניעת שחיקת עובדות והטיית כוכבות.

### פירוט מתמטי של המודלים המוגנים:

#### מודל 1: חיזוי אי-הגעה ואיחור דיילת (No-Show Risk Score)
$$\text{RiskScore} = \min\left(100, \max\left(0, 40 \cdot \frac{\text{Lates} + 1}{\text{Total Shifts} + 5} + 25 \cdot E_{\text{shift}} + 20 \cdot D_{\text{city}} + 20 \cdot T_{\text{fatigue}} - 30 \cdot S_{\text{tag}}\right)\right)$$
* *דיילת חדשה:* מתחילה מציון מאוזן של 20% (לא חלוקה באפס ולא 0% שגוי).
* *עייפות ($T_{\text{fatigue}}$):* מזהה פער של פחות מ-8 שעות בין משמרת לילה למשמרת בוקר הבאה.
* *מרחק ($D_{\text{city}}$):* נשען על התאמת עיר מתוך טבלאות `hostesses.city` ו-`projects.final_location` ללא תלות במפות חיצוניות.

#### מודל 2: חיזוי תאריך פירעון ותזרים מזומנים (Cashflow Delay)
$$\text{Expected Date} = \text{Invoice Date} + \text{Terms Days} + \text{Clean Median Delay}$$
$$\text{Expected Date} = \text{RollForwardToBusinessDay}(\text{Expected Date})$$
* *חובות אבודים:* מוחרגים ב-100% מחישוב החציון (`written_off = false`).
* *הצמדה לסבבים:* לקוחות עיריות מעוגלים ל-10 בחודש הבא, ימי שישי/שבת מקודמים ליום ראשון.

#### מודל 3: חיזוי חריגות שעות בהצעת המחיר (Budget Bias Predictor)
$$\text{Historical Bias \%} = \frac{\sum (\text{Actual Unbilled Hours} - \text{Planned Hours})}{\sum \text{Planned Hours}} \quad \forall \text{ Status} \ne \text{'cancelled'}$$
* אירועים שבוטלו מסוננים. תוספות ששולמו דרך `project_changes` אינן נחשבות כחריגה תקציבית.

#### מודל 4: מדד סיכון נטישת לקוחות (Customer Churn Risk)
$$\text{ChurnScore} = \min\left(100, \max\left(0, 35 \cdot \text{CSAT\_Drop} + 30 \cdot \frac{T_{\text{since\_last}}}{\text{Personal Cadence}} + 25 \cdot N_{\text{neg\_tags}} - 30 \cdot N_{\text{future}}\right)\right)$$
* לכל לקוח מחושב המחזור האישי שלו (אירוע בחודש לעומת אירוע בשנה).
* היעדר משוב מוזן כ-3.5 (ניטרלי) במקום 0 שגוי.

#### מודל 5: ביקושים עונתיים וזמינות כוח אדם (Seasonal Demand & Workforce Availability)
$$\text{Expected Shifts}_m = \text{Baseline}_m \cdot S_{\text{Hebrew}}(\text{Holidays}_m) \cdot S_{\text{Academic}}(\text{Exams}_m)$$
* **חגים עבריים נעים:** עגינה בספריית `@hebcal/core` המזהה מועדי תשרי וניסן הנעים על פני חודשי ספטמבר–אוקטובר ומרץ–אפריל (שבהם הביקוש לכנסים עולה ב-45%).
* **שחיקה עונתית במאגר:** תקופות מבחנים באוניברסיטאות (ינואר–פברואר ויוני–יולי) מקטינות את זמינות הדיילות הסטודנטיות ב-35% ודורשות גיוס מקדים.
* **חריגים היסטוריים:** החרגת רבעוני משבר ביטחוני מאימון המודל למניעת עיוות תחזיות.

#### מודל 6: מודל משוב וכיול היפר-פרמטרים לאלגוריתם Smart Match ומדד ג'יני לחלוקת משמרות (Smart Match Closed-Loop Tuning & Gini Shift Fairness)

מודל זה מהווה את **סגירת המעגל ההנדסית (Closed-Loop Optimization)** בין מודול 04 (שיבוץ דיילות), מודול 09 (הגדרות ומשקולות מערכת ב-`SmartMatchPane.jsx`), וביצועי השטח בפועל ב-`assignments` וב-`salary_reports`.

##### א. מנוע השיבוץ הקיים ב-`src/lib/smartMatch.js` (ארבע השכבות):
1. **שכבה 1 · שער בינארי (Binary Gate):** סינון מוקדם קשיח של מועמדות ללא ניקוד:
   $$\text{PassesGate} = (\text{active}) \land (\neg \text{SameDayEvent}) \land (\text{pref} \ne \text{'לא\_לשלוח'}) \land (\text{available}) \land (d \le \text{gateKm}) \land (d \le \text{goalpostKm} \lor \text{has\_car})$$
   *מקרה קצה:* בהיעדר קואורדינטות ($d = \text{null}$), המועמדת אינה נפסלת (חזקת חפות טכנולוגית).
2. **שכבה 2 · נעיצה ועדיפות ידנית (Pinned Preferences):** דיילת שסומנה כ'מצוינת' עבור הלקוח צפה אוטומטית לראש הרשימה.
3. **שכבה 3 · ציון משוקלל ומנורמל (Normalized Composite Score):**
   נרמול משקולות בזמן ריצה כאשר מרכיב כבוי (למשל כאשר `מרכיב_אמינות_פעיל = false`):
   $$w_i' = \frac{w_i}{\sum_{j \in \text{Active}} w_j} \quad \implies \quad \sum w_i' = 1.00$$
   $$\text{BaseScore} = w_{\text{resp}}' \cdot \hat{P}_{\text{resp}} + w_{\text{rel}}' \cdot \hat{P}_{\text{rel}} + w_{\text{prox}}' \cdot S_{\text{prox}}$$
   הערכת הסתברות בייסיאנית מרוסנת (Bayesian Damping) מול ממוצע כלל-ארגוני $C$ עם קבוע $m=3$:
   $$\hat{P} = \frac{k + m \cdot C}{n + m} \quad (\text{מונע יתרון שווא לדיילת עם מענה 1 מתוך 1 לעומת 9 מתוך 10})$$
   וציון קרבה רציף הנחתם בגולפוסט:
   $$S_{\text{prox}} = 1 - \frac{\min(\max(d, 0), \text{goalpostKm})}{\text{goalpostKm}}$$
4. **שכבה 4 · מנוף הוגנות (Fairness Leverage):**
   $$\text{Leverage} = 1 + \text{ratePerWeek} \cdot \min(\max(\text{weeksSinceWorked}, 0), \text{weeksCap})$$
   $$\text{FinalScore} = \text{round}(\text{BaseScore} \cdot \text{Leverage}, 2)$$

##### ב. מדד ג'יני לחלוקת משמרות במאגר (Gini Fairness Coefficient):
למדידת מידת הריכוזיות בחלוקת המשמרות בין כלל הדיילות הפעילות במאגר:
$$G = \frac{\sum_{i=1}^{n} \sum_{j=1}^{n} |y_i - y_j|}{2n \sum_{i=1}^{n} y_i}$$
כאשר $y_i$ הוא מספר המשמרות המבוצעות ע"י דיילת $i$, ו-$n$ הוא מספר הדיילות הפעילות במאגר בחלון הזמן הנבחר.
* **מדרגי ג'יני תפעוליים במערכת Reg-In:**
  * $G < 0.25$: **שוויון יתר (Over-Equality)** – חלוקה אחידה מדי שאינה מתגמלת אמינות ומצוינות.
  * $0.25 \le G \le 0.40$: **טווח פעולה אופטימלי (Optimal Operating Zone)** – איזון הנדסי מושלם: מתגמל ותק ואמינות לצד שימור מאגר חי ותוסס.
  * $0.40 < G \le 0.50$: **אזהרת ריכוזיות מתונה (Moderate Inequality Warning)** – המשבצות נוטות לחזור על אותן דיילות מוכרות.
  * $G > 0.50$: **ריכוזיות יתר קריטית והטיית כוכבות (Superstar Bias Alert)** – קבוצה מצומצמת מבצעת את מרבית המשמרות, נשחקת ומגדילה את שיעור ה-No-Show, בעוד שאר המאגר נוטש מחוסר תעסוקה.

##### ג. כללי כיול היפר-פרמטרים במעגל סגור (Closed-Loop Tuning Heuristics):
המודל מנתח את ביצועי השיבוץ בפועל ומציג המלצות כיול אוטומטיות בתוך `SmartMatchPane.jsx`:
1. **כלל שחיקת כוכבות (Superstar Burnout Rule):**  
   אם $G > 0.45$ ובמקביל שיעור העזיבה בקרב דיילות ותיקות עלה ב-$>15\%$ $\implies$ המלצה להעלות את `שיעור_בונוס_הוגנות_לשבוע` מ-`0.02` ל-`0.05`.
2. **כלל אימוץ נמוך של דרג 1 (Low Tier-1 Adoption Rule):**  
   אם פחות מ-65% מהשיבוצים בפועל נבחרו מתוך 3 המועמדות המובילות של האלגוריתם (הרכזות עוקפות ידנית) $\implies$ המלצה לכייל את המשקולות: בדיקה האם העקיפה נובעת מאיחורים (להעלות `משקולת_אמינות`) או ממרחק נסיעה (להעלות `משקולת_קרבה`).
3. **כלל איחורים מונחי מרחק (Distance-Induced Lateness Rule):**  
   אם מעל 25% מהאיחורים הבינוניים/כבדים התרחשו בשיבוצים במרחק $>25$ ק"מ $\implies$ המלצה להעלות את `משקולת_קרבה` מ-`0.30` ל-`0.40` ולהקשיח את `גולפוסט_מרחק_קמ` מ-40 ק"מ ל-30 ק"מ.

### 6.7 הנחיות הנדסיות לממשק משתמש במקרי קצה תפעוליים (Operational UX & Production Hardening)

כדי להבטיח שהמערכת עומדת בסטנדרטים הגבוהים ביותר של מערכות תעשייתיות (Production-Ready) ותבריק בהדגמות חיות ובראיונות עבודה, המודול כולל 5 מנגנוני גימור אופרטיביים:

1. **טיפול אלגנטי במצבי אפס נתונים (Zero/Empty States):**
   * כאשר סינון משתמש מחזיר 0 רשומות (למשל: סינון לפי שנת 2027 שטרם החלה, או לקוח ללא פעילות), המסך אינו מציג גרפים שבורים או טבלה ריקה ומנוכרת.
   * מוצג רכיב Empty State ייעודי עם איור עדין, הסבר ברור: *"לא נמצאו פרויקטים בטווח שנבחר"*, וכפתור פעולה מהיר: `[אפס את כל הסינונים]`.

2. **ביצועים, מניעת עומס ו-Caching מול Gemini API:**
   * **Client-Side Aggregation:** חישובי הממוצעים והפילוחים מבוצעים בדפדפן בעזרת `useMemo` ונשמרים בזיכרון, ללא קריאות שרת חוזרות בעת מיון עמודות בטבלה.
   * **Gemini Response Caching:** תקציר המנהלים השבועי מ-Gemini נשמר ב-`sessionStorage` (או בטבלת cache ב-DB) למשך 6 שעות. מעבר בין לשוניות או רענון דף אינו מייצר קריאת API חוזרת ואינו שורף טוקנים מיותרים.
   * **Debouncing בחיפוש:** שורת החיפוש החופשית מוגנת ב-Debounce של 300ms כדי למנוע הצפת קריאות בזמן הקלדה.

3. **חותמת עדכניות נתונים ורענון יזום (Data Freshness Timestamp):**
   * בפינת סרגל הסינון מופיע מחוון עדין: `⏱️ עודכן לאחרונה: היום ב-10:45` לצד כפתור אייקון `[🔄 רענן נתונים]`.
   * מעניק למנהלת הכספים ולמנכ"ל ביטחון מלא שהם מביטים בנתוני אמת עדכניים לאחר סגירת אירוע או תשלום חשבונית.

4. **רספונסיביות מלאה למובייל ולטאבלט (רכזי שטח ולוגיסטיקה):**
   * מנהלת הלוגיסטיקה ומנהלת הגיוס פועלות לעיתים קרובות מהשטח או מטאבלט בעמדת הרישום.
   * כרטיסיות ה-KPI מאורגנות ב-Grid גמיש (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`).
   * הטבלאות האופרטיביות כוללות גלילה אופקית מוגנת (`overflow-x-auto`) עם כותרת טבלה מקובעת (`sticky top-0`) המאפשרת עבודה נוחה גם במסכים צרים.

5. **עיצוב ייעודי להדפסה ולייצוא PDF נקי (`@media print`):**
   * בעת הדפסה או ייצוא הדף ל-PDF עבור פגישת הנהלה/דירקטוריון, חוקי CSS ייעודיים (`print:hidden`) מעלימים אוטומטית את סרגל הסינון, כפתורי הניווט, שורת החיפוש וכפתורי הפעולה האופרטיביים.
   * הדוח מודפס בפריסה נקייה על גבי דפי A4 עם שבירת עמודים מסודרת (`break-inside-avoid` לכרטיסיות ולגרפים).

1. **שאילתת `fetchReportsData()` מרוכזת בעליית המסך:**
   ```javascript
   // src/modules/10_reports/api.js
   import { supabase } from '@/lib/supabaseClient'

   export async function fetchReportsData() {
     // שליפה מקבילה של הישויות העיקריות בשאילתות מותאמות אינדקסים
     const [projectsRes, assignmentsRes, quotesRes, hostessesRes, customersRes, paramsRes] = await Promise.all([
       supabase
         .from('projects')
         .select(`
           id, project_number, name, customer_id, event_date, status, closed_at,
           quote_id, quote_version, total_price, total_hours,
           customers (id, name, business_type, payment_terms),
           finance_project_money (
             total_invoice_amount, total_paid_amount, balance_due,
             last_payment_date, is_fully_paid, collection_status
           ),
           project_changes (change_cost, change_price, is_approved)
         `),
       supabase
         .from('assignments')
         .select(`
           id, project_id, hostess_id, shift_start, shift_end,
           actual_start, actual_end, hourly_rate, travel_payment, bonus_amount,
           status, confirmation_status, attendance_status
         `),
       supabase
         .from('quotes')
         .select(`
           id, project_id, customer_id, total_amount, status, created_at,
           quote_services (service_name, quantity, unit_price, cost_estimate)
         `),
       supabase
         .from('hostesses')
         .select('id, full_name, city, phone, is_active, rating'),
       supabase
         .from('customers')
         .select('id, name, created_at, business_type, default_payment_terms'),
       supabase
         .from('params')
         .select('param_name, param_value, description')
     ])

     // בדיקת תקינות ועטיפת שגיאות מסודרת
     if (projectsRes.error) throw projectsRes.error
     if (assignmentsRes.error) throw assignmentsRes.error
     if (quotesRes.error) throw quotesRes.error

     return {
       projects: projectsRes.data || [],
       assignments: assignmentsRes.data || [],
       quotes: quotesRes.data || [],
       hostesses: hostessesRes.data || [],
       customers: customersRes.data || [],
       params: paramsRes.data || []
     }
   }
   ```

### 9.5 הנחיות Recharts בסביבת ממשק עברי (RTL Best Practices)

בעבודה עם `recharts` בעברית יש להקפיד על הכללים הבאים למניעת שיבושי תצוגה:
1. **ציר X הפוך:** כדי שהזמן יזרום מימין לשמאל כמקובל בעברית, מגדירים בציר ה-X:
   `<XAxis dataKey="dateLabel" reversed={true} tick={{ fill: '#64748b', fontSize: 12 }} />`
2. **ציר Y בצד שמאל:** ערכים מספריים נשארים בצד שמאל כמקובל בגרפים פיננסיים:
   `<YAxis orientation="left" tickFormatter={(val) => Number(val).toLocaleString('he-IL')} />`
3. **בועת מידע (Tooltip) מיושרת לימין:**
   ```jsx
   <Tooltip
     content={({ active, payload, label }) => {
       if (!active || !payload?.length) return null
       return (
         <div className="bg-slate-900 text-white p-3 rounded-lg shadow-xl text-right dir-rtl text-xs">
           <p className="font-bold border-b border-slate-700 pb-1 mb-1.5">{label}</p>
           {payload.map((item, idx) => (
             <div key={idx} className="flex justify-between gap-4 py-0.5">
               <span className="text-slate-300">{item.name}:</span>
               <span className="font-semibold dir-ltr">{Number(item.value).toLocaleString('he-IL')} ₪</span>
             </div>
           ))}
         </div>
       )
     }}
   />
   ```
4. **גובה ואחריות גודל (Responsive Container):**
   כל גרף עטוף תמיד ב-`<ResponsiveContainer width="100%" height={320}>` המונע קריסות רינדור בזמן שינוי גודל חלון.

### 9.7 שילוב שירות תקציר המנהלים מ-Gemini (`src/lib/gemini.js`)

קריאת ה-API מוגנת ומבוקרת לפי עקרון החיסכון והעמידות:
1. **פורמט שליחה:** שליחת נתוני המקרו המעובדים בלבד (ללא מידע מזהה אישי או שורות בודדות).
2. **מנגנון מטמון (Caching):**
   ```javascript
   const CACHE_KEY = 'regin_executive_summary_cache'
   const CACHE_TTL_MS = 6 * 60 * 60 * 1000 // 6 שעות

   export async function getCachedExecutiveSummary(macroMetrics) {
     const cached = sessionStorage.getItem(CACHE_KEY)
     if (cached) {
       try {
         const { timestamp, data } = JSON.parse(cached)
         if (Date.now() - timestamp < CACHE_TTL_MS) {
           return data
         }
       } catch (e) {
         sessionStorage.removeItem(CACHE_KEY)
       }
     }

     const freshData = await generateExecutiveSummary(macroMetrics)
     sessionStorage.setItem(CACHE_KEY, JSON.stringify({ timestamp: Date.now(), data: freshData }))
     return freshData
   }
   ```
3. **במקרה של שגיאה או היעדר מפתח API:** המסך מציג באופן שקוף תקציר מחושב מבוסס חוקים קבועים (Deterministic Rule-Based Summary) כדי שהמשתמש לעולם לא ייתקל במסך תקוע.
