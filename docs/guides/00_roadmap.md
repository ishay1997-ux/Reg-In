## 1. מה בונים ולמה בפרוסות אנכיות

REG-IN מחליפה אקסלים וקבוצות וואטסאפ במערכת אחת: לקוח פונה → מפיקים הצעת מחיר מתומחרת אוטומטית → ההצעה מאושרת והופכת לפרויקט → משבצים דיילות באלגוריתם חכם ומכינים לוגיסטיקה → האירוע מתקיים → סוגרים כספית ומחשבים רווח → הכל נצבע בדו"חות מנהלים.

**בונים בפרוסות אנכיות (Vertical Slices).** לא בונים קודם את כל הדאטהבייס ואחר-כך את כל המסכים. לוקחים מודול אחד ובונים אותו מקצה לקצה: הרשאות (RLS) ← מסך רשימה ← טופס ← לוגיקה עסקית ← בדיקה. רק כשהוא עובד שלם — עוברים הלאה.

**סדר התלויות = סדר הבנייה.** מודול שמסתמך על מודול אחר נבנה אחריו. הטבלה בסעיף 2 מראה בדיוק מה תלוי במה.

## 5. הלולאה לכל מודול — איך עובדים עם Claude

### עיקרון-על: הטמפלט ≠ המדריך ≠ מדריך המיקרו
- **מדריך השלב** (`docs/guides/…`, עברית, בשבילכם) = הקובץ שאתה פותח כדי לדעת מה עושים בשלב, עם **שלושת הפרומפטים** המוכנים להדבקה (פתיחה / המשך-בנייה / סגירה) בסעיף ⑥.
- **טמפלט** (`.claude/skills/module-blueprint/template.md` לפתיחה · `.claude/skills/module-close/template.md` לסגירה, אנגלית) = ההנחיות המלאות ל-Claude לפתיחת/סגירת מודול. אתה לא קורא אותו — Claude קורא אותו בעצמו כשהפרומפט (או הסקיל התואם) מפנה אליו.
- **סקיל** (`.claude/skills/module-blueprint`/`module-build`/`module-close`, מ-23/07/2026) = קיצור-הדרך: במקום להדביק את הפרומפט, אתה אומר "פתח מודול N" / "תמשיך לבנות" / "סגור את המודול" והסקיל נטען לבד, קורא את הטמפלט/מדריך-המיקרו ומריץ אותו. הפרומפטים ⑥ נשארים חבילת-ההקשר וה-fallback.
- **מדריך המיקרו** (`docs/micro_guides/module-N.md`, **אנגלית, כתוב ל-Claude**) = התוצר: בלופרינט חי שקלוד עתידי מבצע צעד-צעד. כולל כותרת-מצב ("הצעד הפעיל"), נקודות עצירה מתויגות 🤖 (קלוד מאמת לבד) או 👤 (אתם מאשרים), ו**פרוטוקול עדכון-עצמי** — המדריך מתעדכן תוך כדי הבנייה, וה-Stop hook חוסם סיום סשן אם קוד המודול השתנה בלי עדכון המדריך.

כלומר: **אתה לא כותב תוכנית ולא קורא אנגלית.** אתה מדביק פרומפט עברי ממדריך השלב → Claude בונה בלופרינט → אתה מאשר → Claude בונה ועוצר לאישורך בסוף כל פזה.

## 6. Git בקצרה (הגרסה המלאה ברמת אפס-ניסיון: [reference/git_workflow](reference/git_workflow.md))

- **`main`** — הגרסה הרשמית. ממזגים אליה רק באבני דרך (M1–M5). מוגן.
- **`dev`** — ענף האינטגרציה. לכאן מתנקזת כל העבודה דרך PR. מוגן.
- **ענף לכל מודול** — `ishay/module-N-נושא` (למשל `ishay/module-1-permissions`, `ishay/module-3-quotes`). כאן עובדים בפועל.
- **הזרימה היומית:** `git checkout dev` → `git pull origin dev` → מעבר/יצירת הענף האישי → עבודה → commit קטן ותכוף עם הודעה בעברית → push → PR כשגמור.
- **כללי ברזל:** לעולם לא דוחפים ל-`main`/`dev` ישירות · לעולם לא `--force` · לעולם לא דוחפים `.env.local` · **כל שינוי סכמה עובר דרך קובץ-מיגרציה בעל-שם** (זו הדרך היחידה לשמור על `docs/schema.sql` נאמן ועל היסטוריה הפיכה) · מושכים `dev` לפני פתיחת ענף חדש · ענף שכבר מוזג — לא ערומים עליו עוד commits (כלל 10).

## 7. מבנה הקוד

כל מודול חי בתת-תיקייה משלו תחת `src/modules/` — גבול ברור בין מודולים, שמקל על סשנים עתידיים למצוא את מה שהם צריכים ומצמצם שינויים לא-מכוונים:

```
src/
├── modules/
│   ├── 01_auth/            ← מודול 1   ✅ קיים
│   ├── 02_customers/       ← מודול 2   ✅ קיים
│   ├── 03_quotes/          ← מודול 3   ✅ קיים
│   ├── 04_hostesses/       ← מודול 4   ✅ קיים
│   ├── 05_logistics/       ← מודול 5
│   ├── 06_projects/        ← מודול 6   ✅ קיים
│   ├── 07_dashboard/       ← מודול 7
│   ├── 08_finance/         ← מודול 8
│   ├── 09_settings/        ← מודול 9
│   ├── 10_automations/     ← מודול 10
│   ├── 11_reports/         ← מודול 11
│   └── 12_integration/     ← מודול 12
├── components/             ← רכיבים משותפים (shadcn, layout, עמודים כלליים)
├── contexts/               ← AuthContext (session + הרשאות)
└── lib/                    ← constants · validators · utils
```

**כלל זהב:** קוד שמשמש יותר ממודול אחד (רכיב טבלה, פונקציית עזר) נכנס ל-`components/`/`lib/` — ולא משוכפל בין מודולים (כלל ברזל 14, SSOT).

**המיקומים בפועל של מודול 1** (חלקו תשתית משותפת מחוץ ל-`modules/`): `contexts/AuthContext.jsx` · `components/layout/` (MainLayout, Sidebar, Topbar, ProtectedRoute) · `components/ProfileSettingsPage.jsx` · `lib/constants.js`, `lib/permissions.js`, `lib/validators.js` · `modules/01_auth/` (LoginPage, SystemManagementPage, UsersManagementPage, PermissionsMatrixPage).
