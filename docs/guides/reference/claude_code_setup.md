# 🔌 רפרנס — כיוונון Claude Code חזק (MCP · סקילים · פלאגינים · קונקטורים)

> מקומו בהיררכיית האמת: הוראות תפעוליות בלבד.
> **מסמך רפרנס** — מריצים אותו פעם אחת על כל מחשב חדש, לפני [הקמת הרוטינות](claude_routines_setup.md) (שמצפות שה-Supabase MCP כבר מחובר).

## ① מה נשיג כאן

ה-Claude שלך יהיה **חזק וממוקד** לפרויקט: מחובר ל-**Supabase MCP** (יכול לקרוא את מצב ה-DB האמיתי — טבלאות, RLS, פונקציות, אזהרות אבטחה — במקום לנחש), עם **פלאגינים/סקילים** לבנייה וביקורת, ו**בלי רעש** שמבזבז לו קשב (context). זה קריטי לבניית כל מודול. ⏱️ ~15 דקות.

**עיקרון-על:** Claude חזק = Claude **ממוקד**. פחות כלים לא-רלוונטיים = תשובות טובות יותר. מוסיפים רק מה שבאמת עוזר לסטאק שלנו (React/Vite/Supabase/Tailwind).

## ④ החלק שלך

### א. MCP — **כבר מגיע עם הריפו, רק לאשר ולהתחבר**
זה החלק הכי חשוב. הריפו כולל קובץ `.mcp.json` (בשורש) שכבר מגדיר את **שרת ה-Supabase MCP** — שרת מתארח (HTTP) עם התחברות OAuth, **בלי אף סוד בקוד**. אתה לא מתקין כלום; רק מאשר:

1. הרץ `claude` **בתוך תיקיית הריפו**.
2. בהרצה הראשונה תופיע בקשת אישור לשרת חדש (`supabase … Pending approval`). **אשר אותו.**
3. עבור את תהליך ההתחברות (OAuth בדפדפן) לחשבון ה-Supabase שלך.
4. בדוק שהצליח:
   ```
   claude mcp list
   ```
   צריך להופיע: `supabase … ✔ Connected`. (ובתוך Claude: הפקודה `/mcp`.)

**למה זה עושה את Claude חזק:** הוא קורא את ה-DB האמיתי במקום להסתמך על תיעוד שאולי התיישן.

> ℹ️ **חריג לכלל ברזל 17:** ל-OAuth אין "פרומפט מסירה" 🧩 — התחברות לחשבון היא פעולה שרק אתה יכול (ורק אתה צריך) לעשות, ואף Claude לא אמור לגעת בפרטי ההתחברות שלך.

⚠️ **גבול חשוב:** שינויי-סכמה (טבלאות/RLS) תמיד עוברים דרך **זרימת המיגרציות בעלות-השם** (כללי הברזל 5/10/12 ב-`CLAUDE.md`) — ‏`execute_sql` של ה-MCP הוא לקריאה ובדיקה בלבד; החלת שינוי-סכמה נעשית דרך `apply_migration` על קובץ-מיגרציה, אחרי שער ה-typed-echo. (רוצים להגביל את השרת ל-read-only? אפשר — ר' ⑧.)

### ב. פלאגינים + סקילים — כלי בנייה וביקורת
פלאגינים מוסיפים פקודות וסקילים (יכולות) ל-Claude. הפקודה `/plugin` (בתוך Claude) פותחת את הקטלוג.

- התקן את הרלוונטיים **לעבודה על הפרויקט**: ביקורת-קוד ו-PR, פיתוח-פיצ'ר מודרך (feature-dev), עיצוב-פרונט (frontend-design), עזרי-commit. הסקילים מגיעים יחד עם הפלאגין.
- בדיקת פעילות: `/help` יציג את הפקודות/הסקילים שנוספו (למשל `/code-review`, `/commit`).
- 💡 **השמות והחבילות מתעדכנים** — אל תסתמך על שם ששמעת; **פתח `/plugin` וראה מה זמין עכשיו**. (בפרויקט הזה שימושיים במיוחד `playwright`, `chrome-devtools` ו-`supabase`.)

### ג. קונקטורים — **לא צריך כאן**
"קונקטורים" (Connectors) שייכים ל-claude.ai (הצ'אט בדפדפן). ב-Claude Code (טרמינל) עובדים עם **MCP**, לא עם קונקטורים — אין מה להקים. ל-GitHub הפרויקט משתמש ב-`gh` CLI (ר' כללי Git ב-`CLAUDE.md`), אז גם שם לא צריך קונקטור.

### ד. מה להוריד / לא לחבר (רעש)
כל MCP/קונקטור מיותר מנפח את הקשב של Claude ומסיח אותו. אם `claude mcp list` מציג חיבורים שלא קשורים לפיתוח — למשל **Booking.com, Tripadvisor, Gmail, Calendar, Google Drive, Make** — הם מגיעים מחשבון claude.ai שלך; **אל תחבר אותם** לעבודה על הפרויקט (ואפשר לנתקם בהגדרות claude.ai).
- שרת MCP מקומי מיותר שהתקנת: `claude mcp remove <name>`.
- **אצבע-אמה לפרויקט הזה:** מספיק **Supabase MCP** (+ אולי כלי-דפדפן לבדיקות, אם תרצה). כל השאר — רק אם באמת צריך.

## ⑤ החלק של Claude

אחרי האישור וההתחברות — Claude מאמת שהחיבור חי, מריץ `claude mcp list`, ומסכם בעברית מה מחובר ואילו סקילים/פלאגינים פעילים.

## ⑥ 📋 הפרומפט להדבקה

```
היי Claude. הרצתי אותך בתוך תיקיית הריפו ואישרתי את שרת ה-Supabase MCP.
הצג `claude mcp list` ותאמת שאתה מחובר ל-Supabase — קרא נתון אמיתי מה-DB
(כמה שורות יש בטבלת roles? התשובה הנכונה: 5). אם זה עובד — סכם לי בעברית
מה מחובר ואילו סקילים/פלאגינים פעילים; אם לא — הסבר מה חסר.
```

## ⑦ בדיקת קבלה

- [ ] `claude mcp list` מציג `supabase … ✔ Connected`.
- [ ] בתוך Claude, `/mcp` מציג את `supabase`.
- [ ] Claude מצליח לקרוא נתון מה-DB (למשל: `roles` = 5 שורות).
- [ ] `/help` מציג את הסקילים/הפקודות שהתקנת (אם התקנת פלאגינים).

## ⑧ אם משהו השתבש

- **`supabase … Needs authentication` / `Pending approval`** — הרץ `claude` בתוך תיקיית הריפו, אשר את השרת כשמבקש, והשלם את ה-OAuth בדפדפן.
- **`claude mcp list` לא מזהה supabase / ריק** — כנראה אתה לא בתוך תיקיית הריפו (`.mcp.json` יושב שם). `cd` לריפו, ו-`git pull` שיהיה לך הקובץ העדכני.
- **Windows / npx** — שרת ה-Supabase הוא HTTP (בלי npx), אז אין בעיה. אם בעתיד תוסיף שרת stdio מבוסס `npx` והוא לא עולה — נסה `cmd /c npx ...`.
- **רוצים read-only ל-Supabase MCP** — אפשר להוסיף `&read_only=true` ל-URL ב-`.mcp.json`, אבל שימו לב: הקובץ **מקומט בריפו** (שינוי בו נוגע בכל מכונה שמושכת אותו), ו-read-only יחסום גם את `apply_migration` — כלומר החלת מיגרציות תעבור ל-CLI/סטודיו. לאמת את הפרמטר בתיעוד Supabase MCP לפני שינוי.
- כל דבר אחר — הצג ל-Claude את הפלט המלא של `claude mcp list` ובקש ממנו לאבחן.

## ⑨ 🎚️ בונוס — איזה מודל ואיזו רמת-מאמץ לכל סוג עבודה

Claude חזק זה גם Claude **מכוון-נכון** למשימה — לא רק מחובר-נכון. שני צירים נפרדים לגמרי, שלא כדאי לערבב:

- **דגם + רמת-מאמץ** = כמה עמוק Claude "חושב" **בתגובה בודדת**. יש **5 רמות אמיתיות** בממשק (`Faster ← נמוך · בינוני · גבוה · אקסטרה · מקס → Smarter`). ⚠️ **הרמות לא שקולות בין דגמים** — לפי תיעוד Anthropic הרשמי, "Sonnet ב-`high` שקול בעוצמה ל-Sonnet-הקודם ב-`max`", ו"Fable ב-`low` יכול לעלות על `xhigh`/`max` של דגם אחר". כלומר `high`/`max` הן תוויות **יחסיות לסולם הפנימי של אותו דגם**, לא יחידת-מידה אחידה — אי אפשר להניח ש"Opus ב-X" ו-"Sonnet ב-X" הם אותו כוח-חישוב.
- **"אולטרא-קוד" (הנקודה השישית בסליידר)** = **לא** רמת-מאמץ בכלל. זה מתג נפרד לגמרי — האם להריץ **תזמור-רב-סוכנים** (הרבה תת-סוכנים במקביל). יקר משמעותית; דלוק רק אם מבקשים את זה במפורש.

| מצב בפיתוח | דגם | מאמץ | Plan/Auto | סוכנים |
|---|---|---|---|---|
| פתיחת מודול (בלופרינט) | Opus/Fable | high–xhigh | **Plan (חובה, כלל 2)** | 1, +1-2 סוכני-ביקורת לפני הגשה |
| בנייה שוטפת לפי מדריך-מיקרו מאושר | Sonnet | high (ברירת-מחדל; `xhigh` רק אם מרגיש חוסר) | Auto — המדריך *הוא* התוכנית | 1 |

| לוגיקה עסקית מורכבת (תמחור, Smart Match, נוסחאות) | Opus/Fable | high–xhigh | Plan אם זו הכרעת-§7 | 1, שקלו council להחלטה כבדת-טרייד-אוף |
| UI/מסכים/מוקאפים/טפסים | Sonnet | medium–high | Auto | 1 |
| תיקון-באג ממוקד (מיקום ידוע) | Sonnet | medium | Auto | 1 |
| דיבוג לא-ברור / רגרסיה מסתורית | Opus | high | Auto (חקירה, לא מבנה) | 1, אולי Explore-agent |

| טריאז' / הכרעת-§7 | Opus/Fable | high | Plan אם משנה תוכנית פעילה | 1 — ההכרעה שלך, לא פאן-אאוט |

| מחקר/סריקה רחבה | Sonnet | medium | Auto, Explore-agent | לפי היקף |
