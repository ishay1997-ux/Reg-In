## ④ החלק שלך — מבנה ה-Branches

- **`main`** — הגרסה הרשמית והיציבה. נוגעים בה רק באבני דרך (M1–M5). מוגן — אי אפשר לדחוף אליה ישירות.
- **`dev`** — ענף האינטגרציה. לכאן מתנקזת העבודה של שניכם, דרך Pull Request. גם הוא מוגן.
- **ענף אישי לכל מודול** — כאן עובדים בפועל בכל יום. פורמט: `עמית/module-N-נושא`, למשל `amit/module-2-customers`.

### הזרימה היומית
```bash
git checkout dev
git pull origin dev

git checkout -b amit/module-2-customers   # בפעם הראשונה על מודול
# (בפעמים הבאות: git checkout amit/module-2-customers)

# ...עובדים, Claude כותב קוד...

git add .
git commit -m "מודול 2: מסך רשימת לקוחות + טופס הוספה"
git push origin amit/module-2-customers
```

### מיזוג (Merge) — דרך Pull Request, לא משורת הפקודה
1. GitHub → הריפו → **Pull requests** → **New pull request**.
2. `base: dev` ← `compare: amit/module-2-customers`.
3. תיאור קצר → **Create pull request**.
4. **ישי** נכנס, עובר על השינויים, ומאשר (**Merge pull request**).
5. שניכם: `git checkout dev && git pull origin dev` — כדי לקבל את העדכון.

> 🧩 **פרומפט לקלוד בדפדפן** (פתיחת PR — הדבק בתוסף הכרום כשאתה ב-GitHub; החלף את שם הענף בענף שלך):
> ```
> אני בריפו Reg-In ב-GitHub. פתח Pull Request חדש: base: dev ← compare: <שם-הענף-שלי>.
> כותרת קצרה בעברית שמתארת מה השתנה. צור את ה-PR והראה לי את סטטוס בדיקות ה-CI.
> אם ה-CI אדום — העתק לי את הודעת השגיאה המלאה; אל תמזג כלום בעצמך.
> ```

### כללי ברזל
- 🔒 לעולם לא דוחפים `.env.local` ל-Git.
- 🗄️ שניכם חולקים פרויקט Supabase אחד — **תאמו כל שינוי סכמה מראש** (הודעה בוואטסאפ לפני migration).
- 🧩 עובדים ברוב הזמן בתיקיית המודול שלכם (`src/modules/NN_name/`) — כך נמנעים conflicts.
- 🔄 מושכים `dev` כל בוקר לפני שמתחילים.
- 💬 commit קטן ותכוף, הודעה ברורה בעברית.
- ⚠️ conflict? לא נבהלים — עוצרים, שולחים צילום מסך, פותרים יחד עם ישי.

## ⑤ החלק של Claude — תרגול PR

Claude מלווה אותך בשינוי-תרגול **זעיר ומוסכם מראש**: הוספת שורה ב-README הראשי בטבלת "מי זה מי" (למשל עדכון קטן/תיקון). המטרה: לעבור פעם אחת על כל הזרימה (ענף → commit → push → PR → אישור ישי → merge → pull) לפני שעושים את זה עם קוד אמיתי.

## ⑥ 📋 הפרומפט להדבקה

```
היי Claude. אני עמית. קרא CLAUDE.md ו-docs/guides/amit/04_git_and_module_workflow.md.
תלווה אותי בתרגול PR מלא: ניצור ענף, תעשה שינוי טקסט זעיר ומוסכם (משהו קטן ב-README),
נעשה commit ו-push, ואני אפתח PR ב-GitHub. תסביר לי כל שלב לפני שאני מריץ אותו.
```

**לולאת המודול (לשימוש כשמתחילים מודול אמיתי):** הפרטים המלאים והפרומפטים ב-[docs/guides/00_roadmap.md §5](../00_roadmap.md) — כל מדריך מודול (06–10 במסלול שלך) כולל את הפרומפט המדויק לפתיחה ולסגירה.

## ⑦ בדיקת קבלה

- [ ] הענף התרגולי נוצר, ה-commit בוצע, וה-push עבר.
- [ ] PR נפתח ב-GitHub, ישי אישר, וה-merge הצליח.
- [ ] `git checkout dev && git pull` מציג את השינוי שלך.

## ⑧ אם משהו השתבש

- **`git push` מציג "rejected"** — מישהו דחף לפניך; הרץ `git pull` ואז נסה שוב.
- **conflict בזמן pull/merge** — אל תלחץ שום דבר; צלם מסך ותשלח לישי/Claude.
- **PR לא מופיע ב-GitHub** — ודא שדחפת בהצלחה (`git push` בלי שגיאה) ושבחרת `base: dev` נכון.
