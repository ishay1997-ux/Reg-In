# 🧠 שלב 04c — לעבוד נכון עם Claude (פרומפטים · טוקנים · כלים · קיצורים)

> מקומו בהיררכיית האמת: הוראות תפעוליות בלבד.
> **מתי:** אחרי [04b](04b_claude_code_power_setup.md) (Claude מחובר ומכוונן) ולפני/במקביל ל-[05](05_claude_routines_setup.md). זה מדריך **קריאה** — אין בו צעדי התקנה.
> **למי:** למי שאף פעם לא עבד עם Claude Code. יוצא מנקודת הנחה שאתה לא יודע כלום — וזה בסדר גמור.

## ① מה נשיג בשלב הזה

תבין איך Claude Code "חושב", איך לכתוב לו בקשות שמחזירות בדיוק מה שרצית, איך לא לשרוף טוקנים סתם, איזה כלי מתאים לאיזו משימה, וכמה קיצורי מקלדת שיחסכו לך זמן כל יום. ⏱️ ~20 דקות קריאה, מחזיר את עצמו כבר ביום הראשון.

---

## ② איך Claude Code חושב — שלושה דברים שמסבירים הכל

1. **לכל שיחה יש "קשב" (context) מוגבל.** כל מה שנאמר בשיחה — הבקשות שלך, הקבצים שהוא קרא, הפלט של פקודות — נכנס לחלון הקשב. כשהחלון מתמלא, Claude מתחיל "לשכוח" את ההתחלה או לדחוס אותה. **מסקנה:** שיחה = משימה. סיימת משימה? `/clear` ותתחיל נקייה.
2. **Claude לא זוכר כלום בין שיחות.** כל שיחה חדשה מתחילה מאפס. מה שכן נטען אוטומטית: `CLAUDE.md` (כללי הברזל). זו בדיוק הסיבה שהפרויקט בנוי על **קבצים** — מדריך המיקרו, STATUS, היומנים. הזיכרון של הפרויקט חי בריפו, לא בצ'אט.
3. **Claude קורא קבצים לבד — ומהר.** אתה לא צריך להדביק לו קוד או מסמכים. תגיד לו *איפה* (`קרא את docs/micro_guides/module-2.md`) והוא יקרא בעצמו. זה גם יותר מדויק וגם חוסך טוקנים (ר' ⑤).

## ③ מצבי עבודה — ומתי Plan Mode

ל-Claude Code שלושה מצבי אישור (מחליפים ב-`Shift+Tab`):

| מצב | מה קורה | מתי |
|---|---|---|
| **רגיל (default)** | Claude מבקש אישור לפני כל עריכת קובץ/פקודה | ברירת המחדל שלך ברוב הזמן |
| **Auto-accept** | Claude מבצע בלי לשאול על כל צעד | רק כשאתה סומך על המשימה (למשל בנייה לפי מדריך מיקרו מאושר) ונשאר ליד המסך |
| **Plan Mode** | Claude רק קורא וחוקר — **לא נוגע בקבצים** — ומגיש תוכנית לאישורך | חשיבה לפני עשייה |

**מתי Plan Mode? (זו ההכרעה הרשמית של הפרויקט, כלל ברזל 2 ב-`CLAUDE.md`):**
- ✅ **כן:** פתיחת מודול (בלופרינט), סגירת מודול, הכרעות §7, שינוי כיוון מהותי, וכל שאלה בסגנון "מה כדאי לעשות".
- ❌ **לא:** בנייה שוטפת עם פרומפט 2 (המשך-בנייה). מדריך המיקרו **הוא** התוכנית המאושרת — סבב תכנון נוסף על כל צעד = בזבוז זמן וטוקנים בלי תועלת. נקודות העצירה 🤖/👤 הן הבקרה.

## ④ איך כותבים פרומפט טוב — המבנה בן 4 החלקים

פרומפט טוב עונה על ארבע שאלות, בסדר הזה:

> **הקשר** (איזה קבצים לקרוא) ← **מטרה** (מה רוצים שיקרה) ← **אילוצים** (מה אסור/חובה) ← **פלט מצופה** (איך נראית הצלחה)

**דוגמה רעה** ❌:
```
תתקן את הבאג בטופס
```
(איזה טופס? איזה באג? איך יודעים שתוקן?)

**דוגמה טובה** ✅:
```
קרא את src/modules/02_customers/CustomerForm.jsx.
בטופס הוספת לקוח, שדה ח"פ מקבל אותיות — צריך לחסום הכל חוץ מספרות (9 ספרות).
אל תיגע בשדות אחרים; הוולידציה נכתבת ב-src/lib/validators.js עם בדיקת יחידה (כלל ברזל 14).
בסוף: הרץ npm run test:run והראה לי שהבדיקה החדשה עוברת.
```

**כללי זהב:**
- **ספציפי מנצח כללי.** "הכפתור לא מיושר בסייד-בר במצב מורחב" ולא "העיצוב שבור".
- **שגיאה? הדבק אותה במלואה.** כל השורות האדומות, כולל ה-stack trace — אל תסכם במילים שלך.
- **בקשה אחת בכל פעם** למשימות בנייה. רשימת 5 דברים שונים בפרומפט אחד = ביצוע בינוני של כולם.
- **אל תמציא פרומפטים למה שכבר יש.** לכל מודול יש 3 פרומפטים מוכנים בסעיף ⑥ של מדריך השלב — הם מנוסחים ומכוונים. הפרומפטים החופשיים שלך הם לתיקונים, שאלות ושינויים קטנים.
- **בקש ראיה.** "הרץ ותראה לי את הפלט" עדיף על להאמין ל"בוצע ✓".

## ⑤ חיסכון בטוקנים — בלי לפגוע בתוצאה

טוקנים = הקצב/עלות השימוש. החדשות הטובות: מה שחוסך טוקנים בדרך כלל גם **משפר** את התוצאה, כי הוא שומר על קשב ממוקד.

1. **הפנה לקבצים, אל תדביק אותם.** `קרא את docs/schema.sql` (Claude קורא רק מה שצריך) במקום להדביק 500 שורות לצ'אט (שנשארות בקשב לתמיד).
2. **`/clear` בין משימות שונות.** סיימת לתקן באג ועובר לפיצ'ר אחר? נקה. שיחה ארוכה עם 4 נושאים = Claude מבולבל + טוקנים על היסטוריה לא רלוונטית.
3. **`/compact` באמצע משימה ארוכה.** אם אתה חייב להמשיך באותה שיחה והיא כבר ארוכה — `/compact` מסכם את ההיסטוריה ומפנה מקום. עדיף `/clear` אם אפשר להתחיל נקי (מדריך המיקרו שומר את ההקשר בשבילך!).
4. **Esc עוצר את Claude באמצע.** רואה שהוא הולך לכיוון לא נכון? אל תחכה שיסיים תשובה שגויה שלמה — Esc, תקן את הכיוון, המשך.
5. **המודל הנכון למשימה** (`/model`): **Opus לחשוב** (בלופרינט, RLS, אבטחה, סגירה) · **Sonnet לייצר** (UI, טפסים, ניתוב). Opus על תיקון צבע כפתור = לשלם על מנוע פרארי בפקק.
6. **אל תסביר מחדש את הפרויקט.** `CLAUDE.md` נטען אוטומטית, ופרומפט ההמשך מפנה למדריך המיקרו. פסקת "אנחנו בונים מערכת לניהול אירועים ו..." בכל פרומפט = טוקנים על מה שהוא כבר יודע.
7. **תפסיק סשן שמסתבך.** אם Claude מנסה לתקן משהו בפעם השלישית בלי הצלחה — עצור (Esc), `/clear`, ונסח את הבעיה מחדש בשיחה נקייה עם השגיאה המלאה. שיחה "טובעת" רק תטבע עמוק יותר.

## ⑥ עבודה במקביל — הכלל בקצרה

הכלל המלא: כלל ברזל 16 ב-`CLAUDE.md`. התמצית:
- **שיחה כותבת אחת בכל רגע** (קוד/תיעוד). שיחה שנייה במקביל — רק לקריאה: שאלות, מחקר, תכנון.
- לא סיימת שיחה? אל תפתח חדשה שכותבת. ה-hooks של הריפו בנויים על ההנחה הזאת.
- `npm run dev` רץ פעם אחת (פורט 5173) — לא בשתי שיחות.

## ⑦ בלוקי 🧩 — "פרומפט מסירה" לתוסף הכרום

יש דברים ש-Claude Code (בטרמינל) לא יכול לעשות: ללחוץ כפתורים ב-GitHub, לפעול ב-Supabase Studio. בשביל זה יש את **תוסף הכרום של Claude** (Claude in Chrome — מתקינים מחנות התוספים של כרום ומתחברים לחשבון Claude שלך).

הזרימה (כלל ברזל 17): כש-Claude Code מגיע לצעד כזה, הוא מדפיס לך **בלוק 🧩** — פרומפט מוכן. אתה: פותח את הדפדפן בעמוד הרלוונטי → פותח את התוסף → מדביק → Claude שבדפדפן מבצע. גם במדריכים עצמם תמצא בלוקי 🧩 מוכנים ליד כל צעד ידני (למשל פתיחת PR ב-[04](04_git_and_module_workflow.md)).

**מה לעולם לא עובר דרך זה:** התחברויות (OAuth) וסודות — אלה תמיד ידניים שלך בלבד.

## ⑨ קיצורי מקלדת שיחסכו לך שעות

**בתוך Claude Code (הטרמינל):**

| קיצור | מה עושה |
|---|---|
| `Esc` | עוצר את Claude באמצע פעולה/תשובה |
| `Esc` פעמיים | קופץ אחורה בהיסטוריית השיחה |
| `Shift+Tab` | מחליף מצב אישור (רגיל ↔ auto-accept ↔ plan) |
| `↑` | הפרומפט הקודם (לעריכה/שליחה חוזרת) |
| `Ctrl+C` | ביטול הקלט הנוכחי / יציאה |
| `/clear` · `/compact` · `/model` · `/mcp` · `/help` | ניקוי שיחה · דחיסה · החלפת מודל · מצב MCP · כל הפקודות |

**ב-VS Code (העורך שמסביב):**

| קיצור | מה עושה |
|---|---|
| `Ctrl+P` | קפיצה לקובץ לפי שם — הדרך המהירה לפתוח כל דבר |
| `Ctrl+Shift+F` | חיפוש טקסט בכל הפרויקט |
| `` Ctrl+` `` | פתיחת/סגירת הטרמינל (שם Claude רץ) |
| `Ctrl+B` | הצגת/הסתרת סייד-בר הקבצים |
| `Ctrl+Shift+P` | לוח הפקודות — כל פעולה של VS Code בחיפוש |
| `Alt+Z` | גלישת שורות ארוכות (נוח בקבצי עברית) |
| `Ctrl+K Ctrl+W` | סגירת כל הטאבים הפתוחים |
| `F12` על שם פונקציה | קפיצה להגדרה שלה |

💡 **טיפ זהב ל-git:** לפני שאתה שואל את Claude "מה השתנה?" — פתח את טאב ה-Source Control ב-VS Code (`Ctrl+Shift+G`) ותראה בעצמך את ה-diff. מהר יותר, ובחינם.
