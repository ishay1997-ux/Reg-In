## ④ החלק שלך

### א. MCP — **כבר מגיע עם הריפו, רק לאשר ולהתחבר**
זה החלק הכי חשוב. הריפו כולל קובץ `.mcp.json` (בשורש) שכבר מגדיר את **שרת ה-Supabase MCP** — שרת מתארח (HTTP) עם התחברות OAuth, **בלי אף סוד בקוד**. אתה לא מתקין כלום; רק מאשר:

1. הרץ `claude` **בתוך תיקיית הריפו**.
2. בהרצה הראשונה תופיע בקשת אישור לשרת חדש (`supabase … Pending approval`). **אשר אותו.**
3. עבור את תהליך ההתחברות (OAuth בדפדפן) לחשבון ה-Supabase שלך.
4. בדוק שהצליח:
   ```
   claude mcp list
   ```
   צריך להופיע: `supabase … ✔ Connected`. (ובתוך Claude: הפקודה `/mcp`.)

**למה זה עושה את Claude חזק:** הוא קורא את ה-DB האמיתי במקום להסתמך על תיעוד שאולי התיישן.

> ℹ️ **חריג לכלל ברזל 17:** ל-OAuth אין "פרומפט מסירה" 🧩 — התחברות לחשבון היא פעולה שרק אתה יכול (ורק אתה צריך) לעשות, ואף Claude לא אמור לגעת בפרטי ההתחברות שלך. אם נתקעת — צילום מסך לישי.

⚠️ **גבול חשוב:** שינויי-סכמה (טבלאות/RLS) תמיד עוברים דרך **זרימת המיגרציות המתואמת** (כללי הברזל 5/10/12 ב-`CLAUDE.md`) — ה-MCP הוא בעיקר לקריאה ובדיקה, לא כדי לשנות DB לבד. (רוצים להגביל אותו ל-read-only? אפשר — אבל הקובץ משותף לך ולישי, לתאם איתו קודם. ר' ⑧.)

### ב. פלאגינים + סקילים — כלי בנייה וביקורת
פלאגינים מוסיפים פקודות וסקילים (יכולות) ל-Claude. הפקודה `/plugin` (בתוך Claude) פותחת את הקטלוג.

- התקן את הרלוונטיים **לעבודה שלך**: ביקורת-קוד ו-PR, פיתוח-פיצ'ר מודרך (feature-dev), עיצוב-פרונט (frontend-design), עזרי-commit. הסקילים מגיעים יחד עם הפלאגין.
- בדיקת פעילות: `/help` יציג את הפקודות/הסקילים שנוספו (למשל `/code-review`, `/commit`).
- 💡 **השמות והחבילות מתעדכנים** — אל תסתמך על שם ששמעת; **פתח `/plugin` וראה מה זמין עכשיו**. (בסביבה של ישי מותקנים למשל `playwright`, `chrome-devtools`, `supabase` — נחמד-לדעת, לא חובה בשבילך.)

### ג. קונקטורים — **לא צריך כאן**
"קונקטורים" (Connectors) שייכים ל-claude.ai (הצ'אט בדפדפן). ב-Claude Code (טרמינל) עובדים עם **MCP**, לא עם קונקטורים — אין מה להקים. ל-GitHub הפרויקט משתמש ב-`gh` CLI (ר' כללי Git ב-`CLAUDE.md`), אז גם שם לא צריך קונקטור.

### ד. מה להוריד / לא לחבר (רעש)
כל MCP/קונקטור מיותר מנפח את הקשב של Claude ומסיח אותו. אם `claude mcp list` מציג חיבורים שלא קשורים לפיתוח — למשל **Booking.com, Tripadvisor, Gmail, Calendar, Google Drive, Make** — הם מגיעים מחשבון claude.ai שלך; **אל תחבר אותם** לעבודה על הפרויקט (ואפשר לנתקם בהגדרות claude.ai).
- שרת MCP מקומי מיותר שהתקנת: `claude mcp remove <name>`.
- **אצבע-אמה לפרויקט הזה:** מספיק **Supabase MCP** (+ אולי כלי-דפדפן לבדיקות, אם תרצה). כל השאר — רק אם באמת צריך.

## ⑤ החלק של Claude

אחרי האישור וההתחברות — Claude מאמת שהחיבור חי, מריץ `claude mcp list`, ומסכם בעברית מה מחובר ואילו סקילים/פלאגינים פעילים.

## ⑦ בדיקת קבלה

- [ ] בתוך Claude, `/mcp` מציג את `supabase`.
- [ ] Claude מצליח לקרוא נתון מה-DB (למשל: `roles` = 5 שורות).
- [ ] `/help` מציג את הסקילים/הפקודות שהתקנת (אם התקנת פלאגינים).

## ⑧ אם משהו השתבש

- **`supabase … Needs authentication` / `Pending approval`** — הרץ `claude` בתוך תיקיית הריפו, אשר את השרת כשמבקש, והשלם את ה-OAuth בדפדפן.
- **`claude mcp list` לא מזהה supabase / ריק** — כנראה אתה לא בתוך תיקיית הריפו (`.mcp.json` יושב שם). `cd` לריפו, ו-`git pull` שיהיה לך הקובץ העדכני.
- **Windows / npx** — שרת ה-Supabase הוא HTTP (בלי npx), אז אין בעיה. אם בעתיד תוסיף שרת stdio מבוסס `npx` והוא לא עולה — נסה `cmd /c npx ...`.
- **רוצים read-only ל-Supabase MCP** — אפשר להוסיף `&read_only=true` ל-URL ב-`.mcp.json`, אבל הקובץ **משותף לשני המפתחים** — לתאם עם ישי לפני שינוי (כלל ברזל 10), ולאמת את הפרמטר בתיעוד Supabase MCP.
- כל דבר אחר — שלח לישי צילום מסך של הפלט של `claude mcp list`.
