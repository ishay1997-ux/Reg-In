### 2. Git (מסנכרן קוד בינך לבין ישי)
- הורד מ-https://git-scm.com/downloads, התקן (ברירות מחדל).
- בדיקה: `git -v`.

### 3. VSCode (העורך שכותבים בו)

### 4. להגיד ל-Git מי אתה (פעם אחת)
החלף לפרטים שלך (**אותו מייל של חשבון GitHub שלך**):

## חלק ד' — להפעיל את הפרויקט אצלך

1. **התקן ספריות** (בטרמינל של VSCode: Terminal → New Terminal):
   ```
   npm install
   ```
   מוריד את `node_modules`. לוקח דקה-שתיים. *לא עולה ל-Git — כל אחד מייצר אצלו.*

   🔻 **נקודת עצירה:** הפקודה נגמרת בלי שורות אדומות של שגיאה, ונוצרת אצלך תיקייה חדשה בשם `node_modules`. אם קפצה שגיאה — צלם מסך ושלח, אל תמשיך לשלב הבא.

2. **צור `.env.local`** בשורש הפרויקט (ליד `package.json`), הדבק את השורות שישי שלח:
   ```
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_ANON_KEY=...
   ```
   **בלי הקובץ הזה הפרויקט לא יתחבר ל-DB. והוא לעולם לא עולה ל-Git.**

3. **הפעל את השרת:**
   ```
   npm run dev
   ```
   חפש בפלט שורה כמו `Local: http://localhost:5173/`. **שים לב למספר הפורט המדויק** (יכול להיות 5173 או 5174) — פתח בדפדפן בדיוק את הכתובת הזו.

4. **בדיקת הצלחה:** אמור להופיע **מסך ההתחברות של REG-IN** עם הלוגו. אם הוא מופיע — אתה מסונכרן עם ישי. 🎉

> 💡 **טיפ מניסיון:** אם שינית קוד ולא רואים שינוי בדפדפן — כמעט תמיד זה או שהקובץ לא נשמר (Ctrl+S), או שהדפדפן פתוח על פורט אחר מזה שהשרת מדפיס. בדוק את הפורט!

## חלק ה' — מבנה הפרויקט (איך להתמצא)

הקוד מסודר לפי מודולים, כל אחד בתיקייה משלו תחת `src/modules/`:

```
src/
├── modules/
│   ├── 01_auth/         ← ישי (מודול 1 - הרשאות). כרגע יש פה קוד.
│   ├── 02_customers/    ← אתה (מודול 2). כאן תתחיל!
│   ├── 03_quotes/       ← אתה (מודול 3)
│   ├── 07_dashboard/    ← אתה (מודול 7)
│   ├── 08_finance/      ← אתה (מודול 8)
│   ├── 11_reports/      ← אתה (מודול 11)
│   └── ...              ← שאר המודולים
├── components/          ← רכיבים משותפים (shadcn)
├── lib/                 ← utils משותף
├── supabaseClient.js    ← החיבור ל-Supabase (חשוב! ראה למטה)
└── App.jsx              ← הקובץ הראשי
```

> ⚠️ **שים לב לנקודה טכנית חשובה:** קובץ החיבור ל-Supabase נמצא ישירות תחת `src/` (לא תחת `src/lib/`). לכן כשאתה מייבא אותו בקוד, הנתיב הנכון הוא:
> ```js
> import { supabase } from "@/supabaseClient"
> ```
> ה-alias `@/` מצביע על תיקיית `src/`. אל תכתוב `@/lib/supabaseClient` — זה שגוי.

**המצב כרגע:** תיקיות כל 12 המודולים כבר קיימות, אבל **רק `01_auth` מכיל קוד** (מסך ההתחברות של ישי). שאר התיקיות ריקות — כל אחד ימלא את שלו. **המודול הראשון שלך: מודול 2 (לקוחות)**, בתוך `src/modules/02_customers/`.

## חלק ז' — שיטת העבודה ב-Git (חשוב מאוד!)

יש 3 סוגי ענפים:
- **`main`** — הגרסה הרשמית היציבה. נוגעים בה רק באבני דרך.
- **`dev`** — ענף האינטגרציה. לכאן מתנקזת העבודה של שנינו.
- **ענף אישי לכל מודול** — כאן עובדים בפועל, בשם `amit/module-2-customers`.

**הזרימה היומית שלך:**
```bash
# 1. כל בוקר - להתעדכן בגרסה המשותפת
git checkout dev
git pull origin dev

# 2. ליצור/לעבור לענף האישי שלך (פעם ראשונה עם -b)
git checkout -b amit/module-2-customers

# 3. ...לעבוד, לכתוב קוד...

# 4. לשמור ולהעלות
git add .
git commit -m "מודול 2: תיאור מה עשיתי"
git push -u origin amit/module-2-customers
```

**כשמודול גמור** — פותחים **Pull Request ל-`dev`** (לא ל-main!) ב-GitHub, וישי מאשר.

**כללי ברזל:**
- 🔒 לעולם לא לדחוף את `.env.local`.
- 🧩 עבוד רק בתיקיות המודולים שלך — ככה אין התנגשויות.
- 🔄 משוך `dev` כל בוקר לפני שמתחילים.
- 🗄️ **שינית טבלה ב-Supabase? הודע לישי מיד** — אתם חולקים DB אחד, וזה משפיע עליו מיד.

> ⏳ **הערה על התזמון:** נכון לעכשיו, מודול 1 (הרשאות) של ישי **עדיין לא מוזג ל-`dev`** — הוא עובד עליו בענף שלו. אתה יכול להתחיל את מודול 2 על בסיס התשתית הקיימת, אבל **האכיפה האמיתית של הרשאות (RLS) תעבוד רק אחרי שישי יסיים וימזג את מודול 1.** עד אז, בנה את המסכים והלוגיקה של הלקוחות — וכשההרשאות יהיו מוכנות, נחבר אליהן.
