# Payroll contract (REG-IN, module 08): build guide for four parallel builders

**What this is.** This is the technical contract for four builders working in parallel. Product decisions in §7.104–108 and the construction plan (`docs/plans/2026-10-13-payroll-end-to-end.md`) are not reopened here. Where something below conflicts with an engineering *proposal* in that plan, this contract wins. Every decision is final unless a W0-CHECK says otherwise.

**Notation.**
- **svc**: execute is granted to `service_role` only.
- **auth**: execute is granted to `authenticated`.
- **anon**: execute is granted to `anon` and `authenticated`.
- **none**: internal only. Execute is revoked from `public, anon, authenticated` and nothing is granted. It is callable only from inside other SECURITY DEFINER functions.
- Every new function is `security definer set search_path to ''` and gets an explicit `revoke execute … from public, anon, authenticated` before any grant.

## 0. Decisions at a glance

| # | Decision | Why |
|---|---|---|
| D1 | Cross-midnight hours use `mod(extract(epoch from (end-start)) + 86400, 86400) / 3600.0`. Equal start and end give 0 hours plus the warning `COMP_DURATION_ZERO`. | It is the same rule already used by `finance_project_money` (migration 20260906083345), `quotes.estimated_hours` and `projectCard.js:minutesBetweenTimes`, so the system keeps one rule. |
| D2 | One global payroll lock: `pg_advisory_xact_lock(7240100401)`, wrapped in `_payroll_lock()`. Every payroll writer takes it first, including the legacy writer, commit, source correction and the August repair. | Month membership can drift between months (an event date can change), so a lock per period does not protect claims. |
| D3 | Writer signal: `set_config('regin.payroll_writer', 'tx:'||txid_current(), true)` inside definer writers only. The guard trigger compares the value with the current `txid`. | It is transaction-local and bound to the transaction. PostgREST cannot set it, because `set_config` is not exposed through `/rpc`. |
| D4 | Collection is materialised exactly once per transaction into `payroll_line[]`. The hash, the inserted lines and the claim all come from that one array. | Under READ COMMITTED, each statement takes a new snapshot, so collecting three times could produce three different sets. |
| D5 | Report identity: a partial unique index on `(period) where report_kind='regular'` plus `unique(original_report_id, supplement_seq)`. The blanket `UNIQUE(period)` is dropped in the same migration, after the partial index exists. | Supplements need this. The old writer keeps its protection because new rows default to `report_kind='regular'`. |
| D6 | All new payroll tables have RLS enabled, **no client policies**, and `revoke all … from anon, authenticated`. Reads go through definer RPCs. | The tables hold hostess contact details and evidence. Table-level ALL privileges plus an empty RLS would otherwise be the only barrier. |
| D7 | Error transport: `_payroll_raise(code, msg, hint)` uses `errcode P0001`, `detail = 'PAYROLL:<CODE>'`, and a JSON `hint` with safe references. Two exceptions are `payroll_operation_snapshot` and `payroll_commit`: they record the failure durably and then **return** `{ok:false, code, message}`. Error `42501` maps to `PERMISSION_DENIED`. | A raise would roll back the durable failure record. |
| D8 | The preview version hash includes no actor information. Authority is re-checked on every call, and the actor is recorded on the operation. | Two managers must be able to compare versions for optimistic concurrency. |
| D9 | The final XLSX is built **in the `payroll` edge function**, in a port of `salaryReport.js` pinned by a parity test. Drafts are built **in the browser** from the same preview response. | The final file must come from the trusted snapshot. Drafts are never stored. |
| D10 | Raw review tokens are generated by SQL (`extensions.gen_random_bytes(32)`, base64url, 43 characters). They are returned once, to the service role only. Only `sha256` is stored. | One place enforces entropy and expiry, and B can test minting without C. |
| D11 | Mail safety guard: a **hard-coded** allow-list `^ishay1997(\+[a-z0-9._-]{1,64})?@gmail\.com$` (case-insensitive) in `payroll/guard.ts` and in a byte-identical `send-email/guard.ts`. Every other address is delivered to `ishay1997@gmail.com` with a banner. There is no environment switch. | Fail-closed: no runtime configuration can widen delivery. Lifting the guard is a deliberate, reviewed code change. |
| D12 | Unknown delivery has a durable state `unknown`. There is never an automatic retry. The only way out is a manual resend after an explicit warning. There is no "mark as sent" action. | The plan forbids inferring the outcome. A manual resend is the only reviewed path. |
| D13 | The new page is a route, `/finance/payroll`. The old dialog stays reachable from FinancePage as a secondary action until cutover A3, which happens **after the conference**. | It keeps a fallback for the live demo at no cost, because the legacy writer is already guarded and month-only. |
| D14 | The legacy `generate_salary_report` keeps its signature and return shape. It is rewritten to call the new collection authority: month-only, lock, conditional claim, month-end rule, and refusal when a review is active. | Otherwise a legacy September issue would claim about 4,000 rows from earlier months, permanently. |
| D15 | `email_log.status` gains the value `'unknown'`, and `email_log` gains the column `intended_recipient`. | Writing `failed` would be false. Leaving out the log row would lose evidence. |
| D16 | Kill switches live in the single-row table `payroll_config`: `final_issue_enabled`, `review_mail_enabled`, `legacy_writer`, `locked_periods`. | One atomic switch each for cutover and rollback. |

### 1.1 August claim repair (migration 9)

**Backup first, inside the same migration:**
```sql
create table seed_snapshot.assignments_payroll_claim_20261014 as select a.*, l.line_id, l.hours as line_hours, l.rate as line_rate, l.travel as line_travel from ...;
```
Then `revoke all … from public, anon, authenticated`.

**Matching rule.** For each line `l` with `report_id = <August id>`, the candidates are assignments `a` where all of these hold:
- `a.project_id = l.source_project_id`
- `a.hostess_id = l.hostess_id`
- `a.salary_report_id is null`
- `a.event_date <= '2026-08-31'`
- the status matches the basis: if `l.line_basis = 'actual'`, then `a.assignment_status = 'finally_approved'`; if `l.line_basis = 'cancellation_compensation'`, then `a.assignment_status = 'released'` and `a.released_from_status = 'finally_approved'`.

**Requirements.** Every line must have **exactly one** candidate, and no assignment may be matched by two lines. If either fails, `raise exception` with the counts, and the whole migration rolls back. Nothing is guessed.

**Write.** Call `_payroll_lock()` and `_payroll_writer_begin()`. Set `salary_report_id = <Aug>` and `travel_amount = coalesce(l.travel, 0)`. The frozen line is the authority, so this restores what the original claim wrote. Value mismatches (`round(actual_hours,2) <> l.hours`, or rate different) are recorded in a `value_mismatch` column of the backup table and do **not** block the repair.

**Post-check (inside the migration):** `count(*) where salary_report_id = <Aug>` must equal 83, else raise.

**W0-CHECK:** run the matching as a SELECT first.
- If it passes (83 lines, each with exactly one candidate): apply the migration.
- If it fails: do not apply it. Instead, add `'2026-08-01'` to `payroll_config.locked_periods` (a configuration migration). Every collection for August then raises `PERIOD_LOCKED` until a manual repair is agreed.

### 1.2 Integrity guard (migration 8)

`assignments_payroll_guard` runs `before insert or update or delete … for each row`. It is SECURITY DEFINER.
- **Insert:** a non-null `salary_report_id` is allowed only for the payroll writer.
- **Delete:** deleting a claimed row is allowed only for the payroll writer. This also blocks cascaded project deletes of claimed rows.
- **Update:**
  - Any change to `salary_report_id` is allowed only for the payroll writer.
  - When `old.salary_report_id is not null`, the following are frozen for everyone except the writer: `actual_hours`, `hourly_rate_snapshot`, `personal_bonus`, `travel_amount`, `hostess_id`, `project_id`, `assignment_number`.
  - `event_date`, the status columns and the attendance columns are **not** frozen. The project date-sync trigger rewrites `event_date` for every row of a project, and freezing status would break module 6/4 flows that do not touch money.
- **Error:** `PAYROLL_CLAIM_IMMUTABLE`.

**`payroll_commit`, step by step:**
1. `set local lock_timeout='5s'`. A lock timeout is caught and returned as `{ok:false, code:'PAYROLL_BUSY', retryable:true}`.
2. `_payroll_lock()`, then the op row `for update`.
3. If the op is already `committed`, return the stored result: commit is idempotent. Any state other than `prepared` gives `OPERATION_STATE`.
4. Actor assert; `ISSUE_DISABLED`; month ended; identity re-check.
5. `_payroll_review_assert_ready_locked(review_id, expected_version)`. If not ready, return `{ok:false, code:'REVIEW_NOT_READY', blockers}` and leave the op `prepared`. It can be resumed after the cause is fixed, because the artifact is still valid when the version is unchanged.
6. Collect once into an array. Lock sources in fixed order: projects `for share` (by project_id), then hostesses `for share`, then `hostess_bank_details` `for share`, then member assignments `for update` (primary-key order), then the payroll `params` rows `for share`. Recompute the version. If it differs from expected, the op becomes `failed` with `PREVIEW_CHANGED` and the function returns.
7. `_payroll_writer_begin()`. Insert `salary_reports` with `report_id = reserved`, the kind, original and sequence, `total_amount`, `report_file_url = artifact_key`, `artifact_*`, `review_id`, `operation_id`, `issued_at`, `issued_by`, `send_status='pending'`, `delivery_state='queued'`.
8. Insert lines (with `assignment_number` and `event_date`). Then the conditional claim `update assignments … where … and salary_report_id is null`. If `get diagnostics` does not equal the line count, `raise CLAIM_MISMATCH`, which rolls back everything.
9. Reconcile the sum of the lines with `total_amount`, raising on a mismatch.
10. The review becomes `issued` with its `report_id`.
11. Reserve the accountant attempt (`initial`, intended = the accountant param).
12. The op becomes `committed`, with `report_id` and `accountant_attempt_id`.
13. Return `{ok:true, report_id, attempt_id, total_amount, line_count}`.

There is no network call inside commit.

## 3. Edge function `payroll` (C)

**Deployment.** `supabase/functions/payroll/`, `verify_jwt: true`. It is a single `POST` handler with `{action, …}`. Gate order follows the precedent: secret, then identity (`auth.getUser()`), then body. Two clients are used:
- `asUser`: anon key plus the caller's Authorization header. Used for every gated user RPC.
- `admin`: the service role. Used for svc RPCs and storage, always passing `p_actor_email` taken from `getUser()`.

**Secrets.** `MAKE_EMAIL_WEBHOOK_URL` (exists) and `PAYROLL_ALLOWED_ORIGINS` (new, comma-separated; W0-CHECK 7). The `app_origin` in the request body must be in that list, else `ORIGIN_NOT_ALLOWED`.

**Response convention.**
- HTTP 200 with `{ok:true,…}` or `{ok:false, code, message, retryable, operation_id?, report_id?}`.
- HTTP 401 or 403 only for identity and permission failures (body has `code:'PERMISSION_DENIED'`).
- HTTP 500 for unexpected errors.
- Why: supabase-js hides the body of non-2xx responses.

**Files.** No imports from `src/`:
- `index.ts`: router.
- `pipeline.ts`: orchestration with injected dependencies.
- `document.ts`: pure port of `buildSalaryReportDocument` plus the supplement extension.
- `money.ts`, `dates.ts`: ports of `toAgorot`/`toShekels`/`toFiniteNumber` and `formatTimestampFull`.
- `xlsx.ts`: `npm:write-excel-file@2.3.10`, returns `Uint8Array`.
- `mail.ts`: ports of `fillEmailTemplate`, `plainTextToEmailHtml`, `templateWithoutAccountantName`, `salaryReportEmailSubject`, plus the review subject.
- `guard.ts`: pure.
- `transport.ts`: the Make POST.
- `README.md`.

C also adds a `Type-check payroll` step to `.github/workflows/ci.yml`.

**`runOperation`, staged:**
1. **snapshot** (svc). `ok:false` returns that code.
2. **build** (`document.ts`). Reconciliation errors (`SALARY_TOTAL_MISMATCH` and the rest) lead to `payroll_operation_fail`.
3. **validate.** MIME xlsx; bytes at most 10 MiB; `ceil(bytes/3)*4` within the attachment cap ported from `src/lib/email.js isAttachmentTooLarge`. Otherwise `ARTIFACT_TOO_LARGE`, then fail.
4. **upload.** `admin.storage.from('finance').upload(prefix + prepare_attempt + '_' + filename, bytes, {upsert:false, contentType})`. Then `sha256` via `crypto.subtle`.
5. **record_artifact.**
6. **commit** (svc). `REVIEW_NOT_READY` and `PAYROLL_BUSY` return with the op still `prepared`.
7. **dispatchAccountant(attempt_id).**

**Filenames.** Regular: `MM_YYYY_Payroll_Report.xlsx`, identical to legacy. Supplement: `MM_YYYY_Payroll_Report_Supplement_<n>.xlsx`, with title `דוח שכר דיילות — <חודש שנה> — השלמה <n>` and an extra header row `דוח מקורי | <original_report_id>` inserted after `הופק בתאריך`. `generatedAt` is the snapshot's `generated_at`, never the edge function's clock.

**`dispatchAccountant` and `processQueued`, one attempt each:**
1. `payroll_attempt_claim`. If `NOT_CLAIMABLE`, skip: someone else is sending it.
2. **Accountant:** download `artifact.key` with `admin`, re-hash it, and if the hash differs from the recorded value, complete as `failed` with `ARTIFACT_HASH_MISMATCH`, then base64-encode it.
   **Personal:** `payroll_review_mint_token` builds the link `${app_origin}/payroll-review/${token}`.
3. **Render.** Read the template from `params` with `admin`, then `fillTemplate` (an unknown token aborts with `TEMPLATE_INVALID` before sending), then guard, then `plainTextToEmailHtml`.
   - Accountant replacements: `[חודש_דיווח_ושנה]` is the period label (plus ` — השלמה n` for supplements). `[שם_רואה_חשבון]` is removed with `templateWithoutAccountantName`, never invented.
   - Personal replacements: `[שם_דיילת]` = snapshot name; `[חודש_דיווח_ושנה]`; `[לינק_בדיקת_שעות]`; `[מועד_אחרון_לתגובה]` = `DD/MM/YYYY HH:mm` Jerusalem time. Subject `סיכום שעות לבדיקה — <חודש שנה>`, plus ` — השלמה n` for supplements. No attachment.
4. **Transport.** POST `{to, subject, body, filename, pdf_base64}` with **all five keys always present** (the existing Make contract, unchanged), with an `AbortController` timeout of 25 s.

### 3.2 Crash points and recovery

| Crash after… | Persisted state | Recovery |
|---|---|---|
| `begin` response lost | op `preparing`, or nothing | Same UUID: `issue` again (idempotent), or `status`. |
| snapshot, build or upload | op `preparing` (an object may be orphaned) | `resume` re-snapshots with `prepare_attempt+1` and a new key. No overwrite. Orphaned candidates are never referenced and are never deleted by this feature. |
| `record_artifact` | op `prepared` | `resume` runs commit, which re-validates the version. |
| commit response lost | op `committed` or `prepared` | `status` tells which. `resume` is safe either way (commit is idempotent). |
| commit, before claim | attempt `queued` | `resume` dispatches: it was never sent. |
| claim (`sending`) | `sending`, lease 120 s | Readers report `unknown`. Only `retry_accountant` with `acknowledge_unknown` works, with an explicit warning. |

### 3.4 XLSX library decision

Use `npm:write-excel-file@2.3.10`, the default (browser) entry. It uses jszip with `generateAsync({type:'blob'})`, and `Blob` exists in Deno; `file-saver` is only referenced at call time. Convert with `new Uint8Array(await blob.arrayBuffer())`.

- unzipping it shows `rightToLeft="1"` in the sheet XML;
- 300 rows build in under 300 ms of CPU, against the edge 2 s CPU limit.
