## חלק ג' — הפעלת הפרויקט אצלך

### 1. התקנת הספריות
בתוך תיקיית `Reg-In`, הרץ:
```
npm install
```
מה זה עושה: מוריד את כל הספריות שהפרויקט צריך (זה ייקח דקה-שתיים, ויוצר תיקייה `node_modules`). **זה תקין שהיא לא הגיעה מ-GitHub — בונים אותה מקומית.**

### 2. יצירת קובץ הסודות `.env.local`
הפרויקט צריך מפתחות חיבור ל-Supabase, אבל **הם לא נשמרים ב-GitHub מטעמי אבטחה**. לכן הם לא ירדו אליך עם ה-clone — צריך ליצור אותם ידנית.
- בקש מישי את שני הערכים (כתובת ה-URL וה-anon key של פרויקט Supabase).
- ב-VSCode, צור בשורש הפרויקט (ליד `package.json`) קובץ חדש בשם בדיוק: `.env.local`
- הדבק לתוכו (עם הערכים האמיתיים שישי ייתן):
```
VITE_SUPABASE_URL=הכתובת_שישי_נתן
VITE_SUPABASE_ANON_KEY=המפתח_שישי_נתן
```
- שמור. **אל תעלה את הקובץ הזה ל-Git לעולם** (הוא חסום אוטומטית ב-.gitignore).

### 3. הרצה
```
npm run dev
```
תופיע כתובת כמו `http://localhost:5173/`. פתח אותה ב-Chrome — אמור להופיע מסך ההתחברות של REG-IN. אם כן — אתה מחובר לאותה מערכת בדיוק כמו ישי! 🎉

## חלק ד' — שיטת העבודה ב-Git (חשוב!)

אנחנו עובדים בענפים נפרדים כדי לא לדרוס אחד את השני. **לפני שאתה כותב קוד, צור לעצמך ענף.**

```
git checkout dev
git pull origin dev
git checkout -b amit/module-2-customers
```
מה זה עושה: עובר לענף האינטגרציה `dev`, מתעדכן לגרסה האחרונה, ויוצר לך ענף אישי למודול 2.

**זרימה יומית** (כל יום עבודה):
```
git add .
git commit -m "תיאור קצר בעברית של מה עשית"
git push origin amit/module-2-customers
```

**מיזוג (כשמודול גמור):** דרך GitHub → Pull requests → New → ממזגים **לתוך `dev`** (לא main!). ישי עובר ומאשר.

**3 כללי ברזל:**
1. כל בוקר — `git checkout dev` ואז `git pull origin dev` לפני שמתחילים.
2. לעולם לא לדחוף `.env.local`.
3. כל אחד עובד בתיקיית המודול שלו (`src/modules/02_customers/`) — ככה אין התנגשויות.
