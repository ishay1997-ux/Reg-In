# הערות אבולוציה והחלטות תשתית (System Evolution Notes)

> **תפקיד המסמך:** ריכוז הרקע להחלטות התשתית המרכזיות שהתקבלו בפרויקט, במטרה לשמר את הזיכרון הארכיטקטוני מבלי להעמיס על ספרי ההפעלה השוטפים (`CLAUDE.md`).

---

## 1. מסד נתונים יחיד (Single Database Environment)
- **ההחלטה:** פרויקט Supabase יחיד (`yfeovxppnfoafmfbdfvh`) משרת הן את סביבת הפיתוח המקומית והן את האתר החי (Production ב-Vercel).
- **ההשלכה הקריטית:** המסד תמיד מקדים את הקוד שנפרס, או שווה לו.
- **האינווריאנט שנגזר מכך:** דפוס **Expand-Contract**:
  - לעולם לא מבצעים `drop column` או שינוי שובר לפני שהקוד הישן ב-Production חדל מלהשתמש בו.
  - כל שינוי סכמה מתחיל בהוספה (תמיכה לאחור) ורק לאחר פריסה מלאה של הקוד מתבצע ניקוי.

## 2. מודל האפליקציה: Single Page Application (SPA) מבוססת Client-Side
- **ההחלטה:** React 19 + Vite 8 ללא שרת Node צד-שרת מותאם אישית (למעט Edge Functions של Supabase לסליקה/אימיילים).
- **ההשלכה:**
  - ניתוב באמצעות React Router 7 עם הישענות על `vercel.json` לשכתוב נתיבים (`"rewrites": [{ "source": "/(.*)", "destination": "/" }]`).
  - שמירת מצבי סינון, חיפוש ועמודי פאגינציה ב-URL Search Params כדי לאפשר רענון וניווט היסטוריה מלא.

## 3. אימוץ שפת עיצוב ו-Tailwind v4
- **ההחלטה:** מעבר ל-Tailwind v4 ישירות דרך `@tailwindcss/vite` ללא קובצי `tailwind.config.js` ו-`postcss.config.js`.
- **ההשלכה:** כל הגדרות העיצוב, המשתנים והטוקנים יושבים ב-`src/index.css` תחת `@theme inline`.
- **הערת RTL:** האפליקציה כולה RTL מובנה. השימוש ב-Tailwind הוא ב-utilities פיזיות (כגון `mr-`, `pr-`, `right-`) כדי להבטיח התנהגות עקבית ואפס תקלות בחישובי מרווחים הפוכים.

## 4. ארכיטקטורת אבטחה והרשאות (RLS & Context)
- **ההחלטה:** RLS מופעל על כל 15 טבלאות המערכת. ה-Context בצד הלקוח (`AuthContext`) רק מציג/מסתיר אלמנטים לנוחות המשתמש; ההגנה האמיתית והבלתי עבירה נאכפת ברמת השורות ב-PostgreSQL דרך פונקציות תפקיד (`current_user_role_id()`).
