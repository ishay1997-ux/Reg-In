# רקע ארכיטקטוני, עקרונות הנדסת תעשייה וניהול ופילוסופיית הבנייה

> **תפקיד המסמך:** מאגר הקשר (Agent Context) להבנת הרקע ההנדסי, הנימוקים העסקיים והחלטות התכנון המרכזיות ב-Reg-In.
> מסמך זה מיועד לקריאת רקע ולא כספר הפעלה שוטף. הסטנדרט ההנדסי המחייב מנוהל ב-[docs/CODE_MAP.md](../CODE_MAP.md) וב-[docs/architecture_and_qa_roadmap.md](../architecture_and_qa_roadmap.md).

## 1. הגישה ההנדסית: הקמת שלד מהלך (Walking Skeleton)

מעבר משלב האפיון (הניירות, ה-ERD ומסכי ה-Mockup) לשלב הבנייה בפועל מחייב ייצוב יסודות מוקדם.
ארכיטקטורת Reg-In נבנתה על בסיס עיקרון ה-Walking Skeleton:
בניית גרסה מינימלית שמחברת את כל שכבות הטכנולוגיה מקצה לקצה כבר במודול הראשון:
**ממשק משתמש (React 19) ⬅️ בקרת גישה והרשאות (RLS & Context) ⬅️ בסיס נתונים (PostgreSQL 17)**.

### היתרונות שנמדדו בפרויקט:
1. **הוכחת היתכנות טכנולוגית מלאה ביום הראשון:** וידוא תאימות של כל הספריות, חיבור ל-Supabase ו-Vite.
2. **איתור מוקדם של מלכודות תשתיתיות:** אילוצי RLS, סנכרון הרשאות ותצורת RTL נתפסו בשלב 0 ולא התגלגלו למודולים מאוחרים.
3. **בסיס בדיקות חי:** מרגע שהשלד עבד, כל מודול נוסף נבנה בפרוסה אנכית שלמה (Vertical Slice) מול תשתית מוכחת.

## 2. עקרונות הנדסת תעשייה וניהול (IE&M Principles)

### א. Lean & Waste Reduction (מניעת Over-Engineering)
- הימנעות משרתי Python/ML מנופחים הדורשים תחזוקה, אירוח נפרד וזמני שיהוי (Latency).
- ניצול מקסימלי של כוח העיבוד המובנה ב-PostgreSQL 17 (אינדקסים חלקיים, פונקציות PL/pgSQL, אילוצי CHECK) ואלגוריתמיקה יוריסטית בדפדפן (Empirical Heuristics & OR).
- תוצאה: 95% מהדיוק העסקי באפס עלות תשתית ובאפס שיהוי רשת.

### ב. Single Source of Truth (SSOT)
- נתונים כספיים וסטטוסים רגישים מחושבים תמיד במקום אחד בלבד:
  - חישובי רווח, הכנסות ושעות מתוכננות: פונקציות שרת ייעודיות (`finance_project_money`).
  - מדרגות תמחור: `quotes.js` בצד הלקוח או פונקציות המרה בשרת.
  - הגדרות ספים: טבלת `params` כ-SSOT מרכזי לכל פרמטרי המערכת (שכר מינימום, מע"מ, ספי אמינות).

### ג. Actionable In-Context Analytics
- תובנות אינן נשארות כלואות במסכי דוחות מבודדים, אלא מוזרקות לתוך זרימות העבודה:
  - התראות חריגה ורווחיות מוצגות בתוך עריכת הצעת המחיר ובסגירת האירוע.
  - מדדי שביעות רצון מוצגים בטבלת הלקוחות ובכרטיס הלקוח.
  - זמינות ומרחקי הגעה מוצגים בתוך אלגוריתם Smart Match לשיבוץ דיילות.

### ד. הפרדת רשויות מול בינה מלאכותית (GenAI Guardrails)
- מודלי LLM אינם מחשבים מתמטיקה, כספים או שעות עבודה.
- מודל השפה משמש אך ורק לסינתזה איכותנית: ניתוח סנטימנט של משוב לקוחות, סיווג תמות וניסוח הצעות שימור.

## 3. מדוע נבחר מודל הפרוסות האנכיות (Vertical Slices)

במקום גישת שכבות מסורתית (בניית כל בסיס הנתונים מראש, לאחר מכן כל ה-APIs ולבסוף כל המסכים), הפיתוח התבצע מודול אחר מודול:
`הרשאות (RLS) ➔ שאילתות ו-RPCs ➔ מסך רשימה וסינונים ➔ טפסים ודיאלוגים ➔ אימותים ובדיקות יחידה/E2E`.

זה מונע "קוד רפאים" שלא נבדק מול UI אמיתי ומאפשר למסור מודולים עובדים ומאומתים בכל שלב.
