# תחזוקה שוטפת ובקרת איכות (Maintenance Runbook)

> **ספר הפעלה תפעולי לשגרות תחזוקה תקופתיות, בדיקות בריאות מסד נתונים, סקירת אבטחה וצ'קליסט העברת מקל**  
> מפה מלאה של כל קובצי המערכת: [docs/CODE_MAP.md](CODE_MAP.md).

---

## 1. שגרות תחזוקה תקופתיות (Periodic Routines)

| תדירות | שם הפעילות | פקודות / כלים | תוצר צפוי וסף אישור |
|---|---|---|---|
| **יומי (תחילת/סוף סשן)** | סנכרון לוח מצב | בדיקת `STATUS.md` ו-`git status` | עץ עבודה נקי ומשימה מוגדרת אחת |
| **שבועי** | בדיקות בריאות מסד נתונים | הרצת 13 הבדיקות מתוך [docs/db_health_checks.md](db_health_checks.md) | פלט מחייב: `נבדקו N · נכשלו 0` |
| **שבועי** | סריקת אבטחה ותלויות | `npm audit` + בדיקת פטורים ב-[docs/reports/security/audit_waivers.md](reports/security/audit_waivers.md) | 0 פרצות חדשות ללא פטור מאושר |
| **חודשי** | סקירת יועצי Supabase (Advisors) | הרצת שאילתות בדיקת אינדקסים, ביצועים ומדיניות אבטחה דרך ה-MCP | 0 אזהרות קריטיות של RLS/Security |
| **חודשי** | סקירת תלויות מיושנות | `npm outdated` ➔ עדכון סלקטיבי מבוקר ➔ הרצת `npm run gate` | שמירה על יציבות חבילות ללא רגרסיות |

---

## 2. נוהל הרצת בדיקות בריאות מסד נתונים (DB Health Checks)

הקובץ [docs/db_health_checks.md](db_health_checks.md) כולל 13 בדיקות קריאה-בלבד המאתרות אנומליות בבסיס הנתונים (כפילויות, יתומי נתונים, שיבושי סטטוסים או סטיות חישוב).

### כלל ברזל בהרצת הבדיקות:
> **רשימה ריקה אינה מהווה הוכחת הצלחה — הפלט הנדרש הוא `נבדקו N · נכשלו 0`.**  
> "0 מתוך 0" מעיד על בדיקה שלא רצה או שאילתה שגויה.

### סדר הביצוע:
1. פתיחת SQL Editor או שימוש ב-MCP להרצת שאילתות הבדיקה.
2. אימות שכל שאילתה סורקת שורות קיימות ומחזירה 0 כשלים.
3. במקרה של ממצא חריג: תיעוד הממצא ביומן ופתיחת משימת תיקון ייעודית (Fix Task) לפי נוהל Expand-Contract.

---

## 3. נוהל סקירת פטורי אבטחה (Audit Waivers Review)

כל פטור מאזהרת אבטחה מתועד במסמך הריכוז [docs/reports/security/audit_waivers.md](reports/security/audit_waivers.md).

בעת סקירה תקופתית יש לוודא:
1. האם שוחררה גרסה מתקנת לחבילה שהייתה תחת פטור.
2. האם תוקף הפטור פג (הגעה לאבן דרך שבה הוסכם לטפל בנושא).
3. אם שוחרר תיקון — הסרת הפטור, עדכון החבילה, והרצת `npm run audit` + `npm run gate`.

---

## 4. צ'קליסט סיום סשן והעברת מקל (Session Handoff Checklist)

לפני סיום סשן עבודה, קלוד ומפתח המערכת מוודאים עמידה בצ'קליסט הבא:

```markdown
- [ ] 1. אימות עץ עבודה: `git status` מציג סטטוס נקי ללא קבצים זמניים/יתומים.
- [ ] 2. הרצת שער איכות: `npm run verify` עובר ב-100% ירוק (לפני PR: `npm run gate`).
- [ ] 3. סנכרון מסמכי אמת:
      - [ ] עודכן `STATUS.md` עם הצעד המדויק הבא.
      - [ ] נרשמה רשומה מתומצתת ב-`docs/CLAUDE_CODE_LOG.md`.
      - [ ] אם נגעה מיגרציה: `docs/schema.sql` עודכן וסונכרן.
- [ ] 4. בדיקת סופי שורה: כל הקבצים החדשים/ערוכים ב-LF (`npm run format:check` ירוק).
- [ ] 5. הגנת סודות: אין סיסמאות או מפתחות שנדחפו לענף.
```
