## 3. פנקס מלכודות שקטות בתיעוד (Silent Traps Register)

| מלכודת שקטה | מדוע התקלה נוצרת | התוצאה והפתרון ההנדסי המחייב |
|---|---|---|
| **קריאת שאלת §7 במקום ההכרעה** | סעיפי `PROJECT_MASTER_sec7.md` גדלים ראש-ואז-זנב: המשפט הפותח מתאר את הדילמה, וההכרעה נחתמת בסוף עם `✅` | ציטוט של תחילת סעיף מצטט את השאלה ולא את התשובה. חובה לקרוא את הסעיף במלואו עד החתימה `✅` |
| **כותרות לא עוקבות או כפולות** | יצירת כותרת `## 3` פעמיים או דילוג על מספר מפילים את `scripts/check-docs-structure.mjs` | כותרות פרקים (`## (\d+)`) ב-`docs/guides` ו-`docs/specs` חייבות להיות ייחודיות ובסדר עולה |
| **תווי כיווניות בלתי נראים (Bidi)** | העתקת טקסט עברי עשויה להדביק תווי LRM/RLM שמכשילים בדיקות string matching | שימוש בטקסט נקי, בדיקה תקופתית דרך `npm run check:bidi` |
| **ספירת משטחים כפולה** | ציון מספר המשטחים הסגורים במספר מקומות יוצר סתירות אוטומטיות | ספירת משטחי Discovery מנוהלת ב-SSOT יחיד ב-`docs/specs/module_04_hostesses/screens-approved.md` |

## 4. מוסכמות עדכון ואדוות (Ripple Protocol — כלל ברזל 13)

התקבלה החלטה שמשנה סכמה, הכרעת מוצר או תהליך עבודה? יש לעדכן באותו סשן לפי הסדר הבא:
1. **עדכון `docs/PROJECT_MASTER_sec7.md` ראשון במפורש** — רישום ההכרעה עם `✅` ותאריך.
2. **עדכון מקור האמת בקוד/DB** — `src/lib/**`, מיגרציה, או `docs/db_roadmap.md` בסשן אפיון.
3. **עדכון מראות מקושרות** — עדכון כל מדריך הנושא תג `🔗 מראת §7.N`. שכפול ללא תג מראה אינו תקין.
4. **יישור `STATUS.md` ו-`docs/PROJECT_MASTER.md §6`**.
