## 1. סקירה כללית, Stack והיררכיית מקורות אמת

**מה זה REG-IN:** מערכת ניהול עסקית מודולרית לחברת אירועים/כנסים (הרשמה, דיילות, לוגיסטיקה), הבנויה מודול-אחר-מודול בעבודת שני מפתחים (ישי ועמית).

**Stack טכנולוגי:**
- React 19 + Vite 8 · JavaScript בלבד (לא TypeScript)
- Tailwind CSS v4 + shadcn/ui + Radix · Lucide (אייקונים) · Geist (פונט)
- Supabase (Auth + Postgres DB)
- ממשק עברי RTL מלא · alias `@/` → `src/`
- לקוח Supabase: `src/supabaseClient.js` → מיובא כ-`@/supabaseClient` (⚠️ לא `@/lib/`)

**מבנה קוד:** כל מודול בתיקייה משלו תחת `src/modules/NN_name/`. משותף → `components/` ו-`lib/`.

**היררכיית מקורות אמת (הגבוה גובר בסתירה):**
1. **`docs/schema.sql`** — סכמת ה-DB. החוזה הטכני הקשיח (שמות עמודות, טיפוסים, constraints).
2. **האפיון המאושר** (`docs/REG-IN - דוח 2 מאושר .docx`) — לוגיקה עסקית, נוסחאות, הרשאות (5.4), זרימות סטטוס.
3. **המוקאפים** (`docs/mockups/`) — שפת עיצוב ופריסה. ממחישים כוונה.
4. **מדריכי המודולים** — מתכון לסדר העבודה.

**מצב נוכחי:** מודול 0 (תשתית) ✅. מודול 1 (הרשאות) בתהליך — מסך התחברות עובד; השלב הבא = צעד 4 (RLS).

## 2. סכמת מסד הנתונים (15 טבלאות)

### 2.1 ליבת ההרשאות (מודול 1)
| טבלה | עמודות מפתח | הערות |
|------|-------------|-------|
| `roles` | `role_id` (PK, serial), `role_name` | 5 תפקידים |
| `modules` | `module_id` (PK, serial), `module_name` | 10 מודולים מוגנים |
| `permissions` | PK מורכב (`role_id`,`module_id`), `permission_level ∈ {edit,view,blocked}` | **טבלת הצומת = המטריצה** |
| `users` | `email` (PK), `role_id`→roles, `full_name`, `status ∈ {active,frozen}` | המייל = זהות Supabase Auth |

**הקשר (לב ה-RLS):** משתמש מזוהה ב-Auth לפי `email` → שורה ב-`users` → `role_id` → חיפוש ב-`permissions(role_id, module)` → `edit`/`view`/`blocked`. ה-DB אוכף, אי אפשר לעקוף מהלקוח.

### 2.2 שאר הטבלאות (דאטה עסקי)
| טבלה | מודול | עמודות עיקריות |
|------|-------|----------------|
| `customers` | 2 | `customer_id`(PK), `customer_type ∈ {private_company,government,production_company,nonprofit}`, `company_name`, `contact_name`, `phone`, `email`, `discount_percent`, `marketing_consent`, `status` |
| `products` | 3 | `sku`(PK), `item_name`, `category ∈ {site,hostess,product}`, `unit`, `base_price`, `cost`, `status`, `image_url` |
| `price_tiers` | 3 | PK(`sku`,`min_qty`), `special_price`, `max_qty` — מחירון מדורג |
| `params` | 9 | `param_id`(PK), `param_name`, `param_value`, `param_type ∈ {pricing_timing,control_alerts,smart_match,templates,integration_tech}` |
| `quotes` | 3 | `quote_id`(PK), `customer_id`, `event_name`, `estimated_hours`, `recommended_hostess_count`, `estimated_guests`, `quote_status ∈ {in_progress,approved,rejected}`, `applied_customer_discount`, `manual_discount`, `pdf_url` |
| `quote_services` | 3 | PK(`quote_id`,`sku`,`line_number`), `qty`, `closing_unit_price`, `color` |

| `salary_reports` | 4 | `report_id`(PK), `sent_date`, `report_file_url` |
| `assignments` | 4 | PK(`project_id`,`id_number`,`assignment_number`), `assignment_status`(5 ערכים), `hourly_rate_snapshot`, `actual_hours`, `personal_bonus`, `salary_report_id` |
| `logistics` | 5 | PK(`project_id`,`sku`,`serial_number`), `planned_qty`, `actual_qty`, `item_status ∈ {not_started,ordered,ready}` |

### 2.3 מכונות מצב (constraints ב-DB)
- **הצעה** `quote_status`: `in_progress → approved → (פרויקט)` / `rejected`
- **פרויקט** `project_status`: `not_started → in_progress → ready → event_finished → awaiting_invoice → awaiting_payment → finished`; `cancelled` בכל שלב
- **שיבוץ** `assignment_status`: `pending → confirmed_available → finally_approved` / `declined` / `released`
- **לוגיסטיקה** `item_status`: `not_started → ordered → ready`
- **משוב** `feedback_status`: `not_sent → sent → completed` / `no_response`

## 4. מערכת העיצוב (נגזר מהמוקאפים בפועל)

**צבעים (משוער מהתמונות, לאימות מול המותג):**

- **אזהרה — כתום/צהוב** `~#F59E0B`: סטטוס "בתהליך", תשלום חלקי.

**פריסה (RTL):**
- **סרגל צד קבוע מימין** (לבן, לוגו REGIN למעלה) עם אייקון+טקסט לכל מודול. פריט פעיל = רקע טורקיז בהיר + טקסט טורקיז.
- **פריטי הניווט בפועל:** לוח בקרה · לקוחות · הצעות מחיר · פרויקטים · דיילות · לוגיסטיקה · כספים ולקוחות · דו"חות · הרשאות · משתמשים · הגדרות מערכת.
- **סרגל עליון:** כותרת המסך (מימין), חיפוש (מרכז), גלגל שיניים + פעמון + אווטאר משתמש (עיגול טורקיז עם אות) + שם/תפקיד (משמאל).

**רכיבים חוזרים:** כרטיסי KPI לבנים (פינות מעוגלות ~16px, צל רך); טבלאות עם אייקוני פעולה בעמודה השמאלית (עיפרון=עריכה, פח אדום=מחיקה, עין=צפייה); תגי סטטוס (pill) בגוני רקע; מודלים למרכז המסך; טוגלים טורקיז; stepper אופקי (עיגולים מלאים טורקיז + וי); דירוג בכוכבים; מסנני chips.
