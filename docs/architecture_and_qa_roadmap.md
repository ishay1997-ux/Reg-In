## 1. הגדרת סיום משימה (Definition of Done — DoD)

משימת פיתוח, הרחבת מודול או תיקון באג מוכרזים כהושלמו אך ורק בעמידה מלאה בכל הקריטריונים הבאים:

1. **אימות מקומי נקי (`npm run verify`):**  
   מעבר 100% ירוק ללא כשלים של בדיקות ה-Lint (ESLint 10), עיצוב קוד וסופי שורה (Prettier, LF בלבד), סוויטת בדיקות יחידה ב-Vitest, ובנייה נקייה של Vite.
2. **כיסוי בדיקות לוגיקה עסקית:**  
   כל שינוי או הוספה של פונקציות לוגיקה טהורה ב-`src/lib/` מלווים בבדיקות יחידה ייעודיות (`*.test.js`) המאמתות מקרים רגילים ומקרי קצה.
3. **משמעת בסיס נתונים (Expand-Contract):**  
   כל שינוי סכמה מתועד בקובץ מיגרציה מתוארך ב-`supabase/migrations/`, עבר את "השער הבלתי-הפיך" מול ישי, הוחל בשרת, ולווה בעדכון מיידי של [docs/schema.sql](schema.sql) וסימון ב-[docs/db_roadmap.md](db_roadmap.md).
4. **סנכרון תיעוד מלא:**  
   - עדכון מצב נוכחי ומשימה פעילה ב-[STATUS.md](../STATUS.md).
   - רישום תמציתי של מהות השינוי ב-[docs/CLAUDE_CODE_LOG.md](CLAUDE_CODE_LOG.md).
   - כל הכרעת מוצר או שאילתה פתוחה נחתמת ב-[docs/PROJECT_MASTER_sec7.md](PROJECT_MASTER_sec7.md).
5. **אבטחת סודות וקרדנצ'לס:**  
   אימות שאין סיסמאות, טוקנים או מפתחות סודיים בקוד המקור.
6. **מיזוג מבוקר דרך Pull Request:**  
   מיזוג לענף `dev` מתבצע דרך PR לאחר מעבר מוצלח של צינור ה-CI ב-GitHub Actions.

## 2. פירמידת הבדיקות ומטריצת בקרת האיכות (QA Matrix)

| שכבת בדיקה | טכנולוגיה / סקריפט | היקף ומטרת הבדיקה | סף מעבר מחייב |
|---|---|---|:---:|
| **Unit Tests** | Vitest (`npm run test:run`) | בדיקת רכיבי UI, פונקציות תמחור, שיבוץ, שכר, ולידציות ומודלים | 100% ירוק (2,400+ בדיקות) |
| **Lint & Complexity** | ESLint 10 + SonarJS (`npm run lint`) | אימות תקני כתיבה, מניעת משתנים מתים, ומורכבות קוגניטיבית ≤ 20 | 0 אזהרות/שגיאות חוסמות |
| **Formatting & LF** | Prettier (`npm run format:check`) | אימות הזנת LF בלבד ואחידות סגנון ללא זיהומי CRLF | 0 קבצים לא תואמים |
| **Accessibility (a11y)** | Playwright + Axe-core (`e2e/accessibility.spec.js`) | סריקת נגישות אוטומטית (כותרות, תגיות ARIA, ניגודיות) על מסכי המערכת | 0 ממצאי Critical / Serious |
| **Smoke Testing** | Playwright (`npm run smoke`) | בדיקת עשן חיה ומהירה במסע משתמש על שרת Dev מקומי (פורט 5173) | קוד יציאה 0 (הצלחה) |
| **End-to-End (E2E)** | Playwright (`npm run test:e2e`) | סימולציית תהליכים עורקיים מול שרת Preview קפוא (פורט 4173) | 100% ירוק |
| **Security Scanning** | Gitleaks (`ci.yml`) | סריקת היסטוריית קומיטים לאיתור סודות ומפתחות חשופים | 0 ממצאים |

## 3. ארכיטקטורת הבדיקות וכללי ביצוע

1. **איסור הזרקת נתוני בדיקה למסד החי:**  
   המערכת פועלת מול מסד נתונים יחיד המשרת גם את סביבת הייצור. בדיקות E2E אינן מבצעות INSERT או UPDATE ישיר למסד, אלא משתמשות ביירוט רשת (`page.route`).
2. **הפרדת סביבות הרצת בדיקות:**  
   - `npm run test:e2e` מורץ אך ורק מול שרת Preview קפוא (`playwright.e2e.config.js`, פורט 4173) כדי למנוע כשלים אקראיים הנובעים מרענוני Vite HMR.
   - `npm run smoke` מורץ מול שרת פיתוח חי (פורט 5173) לצורך אימות מהיר של המערכת המקומית.
3. **פיקסטורות דינמיות:**  
   חל איסור על קידוד מזהים קשיחים (Hardcoded IDs) בבדיקות דפדפן. פיקסטורות נבחרות בזמן ריצה על פי שאילתת תנאי ("ההצעה הראשונה בעלת שורת דיילות").

## 4. שגרות בקרה ותחזוקה (Routine Operations)

- **בדיקות שוטפות בזמן פיתוח:** הרצת `npm run test` במצב האזנה (watch) לבדיקה רציפה של לוגיקה עסקית.
- **אימות טרום-מיזוג:** הרצת `npm run gate` המשלב בדיקת קוד מת (`knip`), שכפול קוד (`jscpd`), ובדיקות שלמות ארכיטקטורה.
- **סקירת אבטחה שבועית:** הרצת `npm audit` וסקירת פטורים פעילים ב-[docs/reports/security/audit_waivers.md](reports/security/audit_waivers.md).
- **בדיקות בריאות מסד נתונים:** הרצת סוללת 13 הבדיקות מתוך [docs/db_health_checks.md](db_health_checks.md).
