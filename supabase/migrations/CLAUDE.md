## 2. חוקי ברזל ארכיטקטוניים ואינווריאנטים (Architectural Invariants)

### 🔻 השער הבלתי-הפיך: הסבר-בעברית + המילה של ישי
החלת מיגרציה על פרויקט Supabase היא פעולה **בלתי-הפיכה**. לפניה מתקיים שער אימות אנושי מחייב:
1. **הסבר מלא בעברית:** קלוד מציג מה המיגרציה עושה, באילו טבלאות/עמודות היא נוגעת, השפעות על RLS, רמת ההפיכות, ומה בדיוק ישתנה במסך שהמשתמשת רואה.
2. **אישור מפורש מצד ישי:** ישי מאשר במילים שלו בצ'אט ("תחיל", "קדימה", "מאשר"). חל איסור מוחלט על אישור גורף מראש או החלה ללא הצגת ההסבר.
3. **החלה עצמאית דרך MCP:** לאחר קבלת האישור, קלוד מחיל את המיגרציה דרך כלי ה-MCP (`apply_migration`). המשתמש אינו מריץ SQL ידנית.
4. **Fallback:** אם ה-MCP אינו זמין בסשן, יש לדווח על כך במפורש ולספק קובץ SQL נקי לחלוטין מהערות בעברית (למניעת שיבושי RTL בהעתקה).

### כלל הפריסה המדורגת (Expand-Contract)
**מסד נתונים יחיד:** פרויקט Supabase יחיד (`yfeovxppnfoafmfbdfvh`) משרת הן את הייצור והן את הפיתוח. האתר החי משרת לקוחות מקוד של קומיט קודם.
**המסקנה ההנדסית:** המסד תמיד מקדים את הקוד שנפרס או שווה לו. אין "מיגרציה שאינה בייצור".

| פעולה בסכמה | מתי מותר לבצע | נוהל ביצוע |
|---|---|---|
| `CREATE TABLE`, `ADD COLUMN`, `CREATE POLICY`, `CREATE FUNCTION`, `CREATE INDEX`, ריכוך אילוץ (`DROP NOT NULL`) | **תמיד מותר** | הקוד הישן בייצור אינו מודע לרכיבים החדשים ואינו נפגע |
| `DROP COLUMN`, `DROP TABLE`, `RENAME`, הידוק אילוץ (`SET NOT NULL`, צמצום `CHECK`), שינוי חתימת פונקציה | **רק לאחר פריסת הקוד החדש לייצור** | אימות ש-`origin/main` אינו קורא עוד את השדה: `git show origin/main:<קובץ> \| grep -n "<שדה>"` |

**הורדות ממתינות:** מתועדות ב-`docs/db_roadmap.md` סעיף 9א. כל מיגרציה הרסנית דורשת קריאה ובדיקה ברשם זה טרם ביצוע.

### אינווריאנטים נוספים לבסיס הנתונים
- **Append-Only בלבד:** מיגרציה שקומטה לעולם אינה נערכת או נמחקת. תיקון מתבצע אך ורק באמצעות מיגרציית תיקון חדשה קדימה.
- **ללא DDL אד-הוק:** חל איסור על הרצת שינויי מבנה (DDL) דרך `execute_sql`. כל שינוי סכמה מתועד בקובץ מיגרציה מתוארך.
- **משיכת גוף חי ב-`CREATE OR REPLACE FUNCTION`:** לפני עדכון פונקציה קיימת, חובה למשוך את הגוף החי מהמסד באמצעות `SELECT pg_get_functiondef('public.<שם>(<טיפוסים>)'::regprocedure)` ולהשתמש בו כבסיס. אין לבנות פונקציה מזיכרון או מקובץ מיגרציה ישן.
- **סנכרון סכמה אוטונומי:** מיד לאחר החלת מיגרציה, קלוד מייצר מחדש את `docs/schema.sql` באמצעות שאילתות מול `pg_catalog` ו-`information_schema` (טבלאות, עמודות, אילוצים, אינדקסים, מדיניות RLS). אין לבקש מהמשתמש לייצא סכמה ידנית.

## 3. פנקס מלכודות שקטות בבסיס הנתונים (Silent Traps Register)

| מלכודת שקטה | מדוע התקלה שורדת ללא שגיאה | התוצאה והפתרון ההנדסי המחייב |
|---|---|---|
| **אי-התאמה בין שם קובץ המיגרציה למספר ב-DB** | חותמת הקובץ נוצרת לפי שעון מקומי (`Get-Date`), בעוד כלי ה-MCP רושם חותמת UTC (פער קבוע של 3 שעות). שימוש עתידי ב-Supabase CLI משווה לפי גרסה ולא לפי שם | ה-CLI עשוי לזהות מיגרציות כמוחלות בחסר ולנסות להריץ אותן שוב. השוואת מיגרציות נעשית תמיד לפי `name` ולא לפי `version` |
| **פונקציית `moddatetime` זזה לסכמת `extensions`** | קריאה ל-`public.moddatetime` נכשלת בסכמה הנוכחית, אך טריגרים ישנים ממשיכים לעבוד בגלל קישור ל-OID היסטורי | טריגרים חדשים של `updated_at` חייבים להגדיר במפורש `EXECUTE FUNCTION extensions.moddatetime('updated_at')` |
| **`REVOKE ... FROM PUBLIC` לא חוסם את `anon`** | ב-Supabase, ברירת המחדל של `ALTER DEFAULT PRIVILEGES` מעניקה הרשאות הרצה ל-`anon` בשם מפורש ולא דרך תפקיד `PUBLIC` | שלילת הרשאות מפונקציה מחייבת פקודה מפורשת: `REVOKE EXECUTE ON FUNCTION X FROM PUBLIC, anon, authenticated` |
| **טבלה חדשה שקטה עקב RLS ריק (Deny-All)** | פתיחת טבלה חדשה עם RLS ללא מדיניות מחזירה 0 שורות במקום שגיאת גישה | מסך ריק מחייב בדיקת policies ב-Postgres לפני חיפוש באגים בקוד ה-UI. טבלאות חדשות מחייבות הוספת policies מתאימות באותה מיגרציה |

## 4. מוסכמות קוד וסדר פעולות במיגרציה (Migration Protocol)

לפני כתיבת מיגרציה חדשה:
1. בדיקת `docs/db_roadmap.md` (צ'קליסט עיצוב והורדות ממתינות).
2. ניסוח שם קובץ תקני: `supabase/migrations/YYYYMMDDHHMMSS_<module>_<description>.sql`.
3. הוספת כותרת תיעוד עברית בראש הקובץ (`-- why: ...`).
4. הצגת הסבר בעברית לישי וקבלת אישור ("השער הבלתי-הפיך").
5. החלה באמצעות `apply_migration`.
6. ריענון `docs/schema.sql` ועדכון `docs/db_roadmap.md` באותו הסשן.
7. ביצוע קומיט משותף לקובץ המיגרציה ול-`docs/schema.sql`.
